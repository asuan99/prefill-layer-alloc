이 페이지는 프로젝트의 설계 좌표계를 고정한다. 아래 그림은 전부 기전을 보이기 위한 개념도이며, 어떤 수치도 측정값이 아니다. 확정된 결과(PD 분리 이득, layer-type 정책 死, 단일 GPU 반응형 동적 제어의 HE0)는 여기서 다시 논증하지 않는다.

1. 중심 주장과 반증 조건

SM 배분형 단일-GPU PD-mux 스케줄러(Bullet/MuxWise 계열)를 hybrid(attention+SSM) 모델로 확장하는 일은 자명하지 않다. Bullet은 이 확장을 "straightforward, future work"로 남겼고 아무도 수행하지 않았다.

자명하지 않음 = 셋 다 성립

  1. generic 예측기(전 층 attention 가정 + online 재보정)가 hybrid에서 다른 최소 SM, 다른 행동을 낸다.
  2. 그 차이가 goodput(TTFT ≤ SLO ∧ 요청내 token-ITL p95 ≤ SLO)에 나타난다. n≥4, 짝지은 CI, 3% 이상, 변화 trace.
  3. hybrid 보정 예측기(attn/SSM 분리)가 그 손실을 고친다.

반증도 결과다

  • 1 없음 → 확장은 자명. 부정 결과로 기록.
  • 1만 → 결정은 다르나 성능은 같다. 상수 튜닝.
  • 1·2만 → hybrid에서 이 계열이 깨지지만 프로파일로 못 고친다. 기전 결과.
금지: "이미 검증됐다" · 충실한 baseline(P_gen+recal) 없이 얻은 우세.

3. pause manager — 상태와 계약

관리자가 소유하는 것

  • 쌍 건너뜀. update_running_batch는 끝에서 KV 슬롯을 전진시킨다. decode만 건너뛰면 step마다 할당이 쌓인다.
  • 스트림 전환. 진입 시 idx0, 해제 시 복귀 인덱스. 각 1회 드레인.
  • 자체 시계. n_max, prefill final 이벤트, 긴급 occupancy.
  • 계측. 정지 iteration은 ITL 표본 제외. 정지된 요청의 실제 토큰 간격은 요청 단위로 따로, 전 arm 대칭.

correctness gate

  • CPU fake 루프: 정지 step에 prepare_for_decode 0회, 재개 후 결과열이 OFF와 동일, 기본값 OFF 바이트 동일, legacy와 true-dual 양쪽.
  • 변이본은 실패해야 한다: decode만 건너뛰는 판, 불변식 (i)/(ii)를 뺀 판.
  • GPU: PAUSE OFF/ON 디코딩 출력 동치, observer effect.
  • 금지 조합 fail-fast: sticky · SLO_SCHED · LA_COORD · TP>1.

"조성"의 세 층 — 누가 정하는가

층요소런타임에 바뀌나정책 비교에서의 지위

U 요청 (사용자 쪽)입력 길이, 출력 길이, 도착 과정, prefix 공유 구조, SLO 등급요청마다워크로드 축 — 엔진이 고를 수 없음

배치 ctx 분포 = U × E. attention 층 비용 ∝ Σctx는 요청 길이와 배치 구성 둘 다에, SSM 층 비용 ∝ bs는 엔진에만 의존한다. 그래서 hybrid가 바꾸는 것은 decode 비용에서 사용자 쪽 성분의 비중이고, transformer 기준 예측기가 틀릴 수 있는 순간은 ctx만 변하고 bs는 그대로인 순간이다(W5 context swing). 기존 결과의 방향도 같다: 모델(M)을 바꿨을 때 결정은 움직이지 않았고(P1.7 4모델, 8B decode SM, layer-type 死), 요청(U)을 바꿨을 때 체제가 바뀌었다(λ0 shape A/B, 수치 인용 금지).

식별 조건이 하나 있다. 단일 모델에서는 조성이 상수라 "조성 포함 vs 미포함"이 재매개화에 불과하다. 조성이 다른 모델 두세 개로 적합하고 나머지 하나를 맞히는 hold-out(A11)이 있어야 "hybrid 때문"을 말할 수 있다.

11. 알고리즘 — 사전등록 전 초안

상수(τ_age, k, n_max, α, 격자, 문턱)는 전부 등록 대상이다. 분기 순서를 문면으로 고정하는 이유는 S0 rev1이 해석 폭만으로 라벨이 뒤집혔기 때문이다.

A1 · P_hyb points 생성

input : 3-a points {(SM,bs,ctx) → itl p50/p95/p99}, (n_attn, n_ssm)
fit   : a0,a1,a2 · m0,m1 · f0,f1 · s_attn(SM), s_ssm(SM), s_mlp(SM)
        residual_p95 = p95|pred−meas| on HELD-OUT points
emit  : ∀SM∈{16,24,34,44,108}, ∀bs, ∀ctx in grid → DecodeLatencyPoint
        heldout_residual_p95_ms = residual_p95
check : every allowed SM has a full bs×ctx grid (missing → estimator skips silently)

A2 · P_gen 두 점 보정

k(SM) = (T_hi − T_lo)/(ctx_hi − ctx_lo)         # applied to ALL layers
T_gen(SM,bs,ctx) = T_lo(SM)·bs/bs_ref + k(SM)·(ctx−ctx_lo)·bs/bs_ref
emit same grid as A1

A3 · P_gen+recal (충실한 baseline)

e ← 1.0
each epoch: e ← (1−α)·e + α·(observed_itl_p95 / T_gen(cur SM, bs, ctx_p95))
T_used = e · T_gen            # fixes level, not the ctx-slope form

A4 · 압력 검출과 규칙 (분기 순서 고정)

pressure := queue_depth>0 ∧ oldest_age > τ_age
if ¬pressure ∨ decode_running_bs==0: NOOP        # 2F9
d_min := min{d : predict(d,bs,ctx_p95).p95 + margin ≤ SLO}
if d_min is None:            NOOP
if d_min < current:          SQUEEZE(d_min)
if d_min == grid.min ∧ pressure ≥ k epochs
   ∧ tpot_after_pause(n_max) ≤ SLO:  PAUSE(n_max)
else NOOP

A5 · Pause manager

enter(n):
  require split_prefill_batch ≠ None ∧ ¬wait_prefill_kernel_done   # (i)
  require ¬r2_admission_limited                                    # (iii)
  return_idx ← cur; drain(prefill, decode); select idx0
  left ← min(n, n_max)                                             # (ii)
each iteration while left>0:
  SKIP update_running_batch AND decode submit (pair)
  ITL sample excluded; per-request gap recorded
  left −= 1
  if prefill_final_submitted ∨ emergency_occupancy: left ← 0      # (iv)
exit(): drain(prefill); select return_idx; resume sampling; emit telemetry
assert ¬(left>0 ∧ r2_admission_limited)

A6 · F1 재정렬 (기본 OFF)

before get_new_batch_prefill():
  est[r] = T_span_total(L_miss(r), all layers, prefill_sm)   # CM-2
  order = sort(waiting_queue, key=est)                       # shortest first
  r with age(r)+est_wait(r) > SLO_TTFT → front (FCFS among them)
  requires priority scheduling OFF (calc_priority is a no-op under fcfs)
radix ON only: L_miss counts tokens from nearest node WITH SSM state

A7 · admission 예산 (CM-5)

kv_ok   = kv_free ≥ Σ_{l∈attn} ctx(r)     # attention layers only
slot_ok = mamba_slots_free ≥ 1            # fixed per request
run_ok  = running_bs < max_running
# radix OFF + explicit max_running ⇒ slot cap == run cap (identity, M0)

A9 / A10 / A11 · 분석·검사·식별

A9  W_queue = forward_entry − wait_queue_entry; S_prefill = prefill_finished − forward_entry
    exclude retract_time>0; S1 F-E · S2 gate#12 · S3 queue trend → UNSTABLE/STATIONARY
A10 fix rule A4; predictors from the SAME 3-a points; open-loop replay;
    D = P(label differs), M = P(same label, different d_min); mutations M3/M5/M1′
A11 fit CM-1 on models M1..Mk, predict held-out M*; "composition matters"
    only if err(P_hyb) < err(P_gen) on M*

12. 알고리즘 배치 지도 — 어디서 돌고, 무엇을 설명하며, 무엇이 다른가

실행 흐름은 다섯 층이다. L0 오프라인(배포 전 CPU), L1 컨트롤러 epoch(케이던스 평가), L2 루프 iteration(매 decode step ∥ prefill span), L3 admission 지점, L4 사후 분석. 주황 테두리가 선행에 없는 요소, 점선 테두리가 선행 규칙의 정의를 바꾼 요소, 검정이 선행 재현(baseline 자격)이다.

선행 cost model 정독 후 정정(2026-10-01). MuxWise 식 2 T_dec = θ1·Σr_i + θ2·bs + θ3는 ctx 비례 항과 ctx 무관 항이 이미 분리돼 있어 단일 모델·고정 SM에서 재적합하면 형식이 깨지지 않는다. Bullet SRM은 커널 무관 roofline이라 SSM 커널의 flop/mem을 넣으면 그대로 쓸 수 있다. 실제로 깨지는 것은 θ 비율의 SM 의존성(X-7), 층 균일 N_PL(X-4), mamba 슬롯의 변수 부재(X-6), 간섭 대리변수(X-5)다. 그래서 P_gen은 "MuxWise 식 2를 hybrid에 재적합 + Bullet식 α 보정"으로 강화했고, 단일 SM·단일 조성에서 P_hyb와 차이가 0에 가까우면 정직한 결론은 "예측기 수준의 확장은 자명하다"이다. 원문 정리: reports/prior_cost_models_bullet_muxwise_2026-10-01.md.

13. 정의의 사각지대 — 이 설계의 정의들이 보지 못하는 것

정의를 바꾸려는 것이 아니라, 정의가 보지 못하는 영역을 먼저 적어 결과 해석과 사전등록이 그쪽으로 새지 않게 하려는 표다. 전부 측정 전이며 근거 등급(코드·정본·분석)은 문서에 있다.

결과를 가장 크게 흔들 수 있는 다섯. ① 요청내 p95 ITL은 PAUSE가 만드는 드문 큰 간격을 가려 PAUSE를 공짜처럼 보이게 한다. ② span 예산은 1층 아래로 못 내려가 긴 입력에서 span 시간이 무한히 늘어나며, 이 경계가 타겟 범위 안에 있다. ③ 정책 비교를 변화 trace로 하기로 했는데 정상성 검사는 그런 trace에 정의되지 않는다. ④ 결정 지점은 CPU 발행 경계일 뿐 GPU 반영 시점이 아니다. ⑤ 조성 분해에 기판 층이 없다.
