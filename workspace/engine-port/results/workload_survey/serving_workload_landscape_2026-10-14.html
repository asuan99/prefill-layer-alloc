서빙 워크로드 지형

LLM 서빙 스케줄링 연구가 어떤 워크로드로 평가하는지를 연구 계열별로 모았다. 질문은 하나다. 이 프로젝트(Nemotron-Nano-9B-v2, A100 한 장, green-context PD-mux)가 일반 워크로드로 평가해야 하는가, long-context 워크로드로 평가해야 하는가.

결론: 둘 중 하나를 고르는 문제가 아니다. 가장 가까운 선행(PD-mux 계열 4편)은 전부 일반 워크로드와 장문 워크로드를 한 세트로 평가한다. 최근접 선행 MuxWise와 DuetServe는 이미 Mooncake Conversation을 쓰고 있다.

권고하는 세트는 네 가지다. ShareGPT는 기존 결과와 연결하는 앵커, Mooncake Conversation은 주 워크로드, OpenThoughts(추론)는 출력이 긴 축, LooGLE은 MuxWise 장문 설정과 직접 비교하는 용도다. 128k를 넘는 초장문은 다른 계열(SP/CP, GPU 여러 장)의 영역이라 main에 넣지 않는다.

1. 연구별 평가 입력 길이

각 막대는 논문이 보고한 입력 길이 범위다. 계열마다 다루는 길이대가 뚜렷이 갈린다. 초록 세로선은 Nano-9B-v2에서 요청당 KV 메모리가 Mamba state 메모리를 넘어서는 지점이고, 빨간 세로선은 모델의 최대 문맥이다.

PD-mux · GPU 내부 SM 분할범용 서빙(PD 분리 · chunked prefill)long-context 목표hybrid · 이종 구조이 프로젝트 제안

3. 관측되는 흐름

T1 장문은 이제 표준 축이다

PD-mux 4편이 모두 장문 워크로드를 하나 이상 넣는다(LooGLE, arXiv-Summary, Long Data Collections, Mooncake). "일반이냐 장문이냐"가 아니라 세트 안에 장문이 있느냐가 심사 기준이다.

T2 Mooncake trace가 공통 기준이 되고 있다

MuxWise·DuetServe(PD-mux)와 Vertumnus(long-context)가 Mooncake trace를 쓴다. MuxWise의 Conversation 평균 입력 7,538에 재사용 문맥 4,496을 더하면 12,034가 되어, 제가 직접 계산한 전체 평균 12,035와 맞는다.

T3 벤치마크 장문은 출력이 짧다

LooGLE 출력 평균 15, L-Eval·LV-Eval은 QA 위주다. Medha는 이 이유로 자체 SWE 워크로드를 만들었다. 출력이 긴 축은 추론 워크로드(MuxWise OpenThoughts 평균 8,374)로 따로 들어온다.

T4 초장문은 다른 계열의 영역이다

100k를 넘는 연구는 거의 모두 GPU 8–128장에서 SP·CP를 쓴다. GPU 한 장에서 SM을 나누는 연구가 이 영역에서 싸우면 비교 대상이 맞지 않는다.

T5 TTFT SLO는 길이로 정규화한다

Bullet은 ms/token, LoongServe는 길이로 나눈 지연, Vertumnus는 입력 길이 구간별 목표, DistServe는 앱별 목표를 쓴다. 우리 A′ 방식(길이별 floor × k)이 이 흐름과 같다.

T6 실 trace는 재생하고, 벤치마크는 Poisson을 붙인다

timestamp가 있는 trace는 축소 재생(MuxWise, Vertumnus), 없는 데이터셋은 Poisson이다. 우리 방법론 게이트 #2(변화 trace)는 실 trace 재생으로 자연스럽게 충족된다.

T7 hybrid × GPU 내부 스케줄링은 비어 보인다

PD-mux 계열은 전부 transformer, hybrid 계열은 캐싱·메모리·장치 분리다. 이번 조사 범위에서 둘이 만나는 연구는 찾지 못했다. "최초"라고 쓰려면 별도 감사가 필요하다(교훈 260).

4. 권고: 워크로드 세트

모든 구성의 기준은 Nano-9B-v2, A100 한 장, radix OFF(현행 결정)다. 네 워크로드가 각각 다른 질문을 맡는다.

5. 확인하지 못한 것과 한계

  • Bullet: 워크로드별 길이 수치가 본문에 없고 CDF 그림으로만 있다. 그림 막대는 profiling 범위(32k)를 근거로 한 근사다.
  • Marconi: 길이 분포가 그림으로만 있다. "수백~수만 토큰"은 본문 서술 기준이다.
  • FlowPrefill: QwenTrace의 구체 길이 통계는 확인하지 못했다(본문 Table 1을 추출하지 않음).
  • Splitwise(Azure 2023 trace)는 이번에 원문을 확인하지 않았다.
  • DuetServe: ISL/OSL이 평균인지 중앙값인지 논문이 밝히지 않는다. Mooncake 값은 전체 trace 평균과 같다.
  • Context Parallelism · Helix: 서빙 trace가 아니라 고정 길이 지연 측정이다(Helix는 시뮬레이터).
  • SQD: 측정은 B200에서 decode 풀을 16 SM으로 제한한 프록시이고, 1M 지점은 모델이 서빙된 262k를 넘는다(저자 공시).
  • Jenga: hybrid 모델(Jamba)은 짧은 MMLU-Pro에서만 평가했다. 장문 arXiv-QA는 transformer(Gemma-2, Ministral)다.
  • 조사 범위: 19편은 원문 평가 절을 확인했다. "hybrid × PD-mux × 실 장문 trace 연구가 없다"는 이 범위에서 찾지 못했다는 뜻이며, 체계적 문헌 조사가 아니다.
  • Mooncake 통계: 공개 jsonl을 직접 내려받아 계산했다(conversation 12,031건, toolagent 23,608건). Vertumnus Table 1과 일치한다.
