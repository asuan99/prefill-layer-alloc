## 메인 세션 독립 검증 (2026-09-04, 감사자와 별개로 실행)

E9가 이 판정의 가장 비싼 주장이므로 메인 세션이 직접 재현했다.

- **파라미터 수는 모델 자신의 인덱스에서 확인**: `model.safetensors.index.json`의 `total_size` = 17,776,454,656 B ÷ 2 (bf16) = **8.888e9**. 감사자가 쓴 8.89e9와 일치.
- **루프라인 재계산**(같은 가정): p90 4,246 tok에서 108 SM·MFU 100% = **242.0 ms**, 64 SM = **408.3 ms**. 400 ms가 100% MFU에서 가능한 최대 프롬프트 = 108 SM **7,019 tok** / 64 SM **4,159 tok**. 감사자 수치와 자릿수까지 일치.
- ★**MFU 48% 역산의 정합성이 감사자가 적은 것보다 강하다**: p50 = 2,795 tok에서 48% MFU가 예측하는 값은 `d44` **560.0 ms** · `plain/cp` **331.8 ms**이고, W1이 실측한 값은 **561 ms** · **325 ms**다(오차 0.2% / 2%). 두 arm의 실측이 하나의 MFU 상수로 이 정확도에 맞는 것은 우연으로 보기 어렵다 ⇒ **루프라인 모형이 이 모델·이 트리에 실제로 전이된다는 독립 증거**이고, 따라서 p90 예측(plain ≈494 ms · d44 ≈833 ms)도 같은 신뢰를 갖는다.
- ⇒ **E9의 결론을 메인 세션도 수용한다**: 등록 층에서 세 arm 전부 400 ms(=`rag`)를 넘고 3000 ms(=`batch_async`)를 밑돌 가능성이 높으므로 `anchor = unique = batch_async` · `neutral` · `ladder = pruned`(500 ms 행만 탈락)가 예측되고, 예측 라벨은 **`ANCHOR_REGISTERED_LADDER_PRUNED`(fork `a`)**다. `FLOOR_NOT_ARM_NEUTRAL`로 가려면 파티션 없는 arm이 **MFU 60.5% 이상**을 내야 하는데 실측은 ≈48%이고 부팅 SD는 2–6%다.
- **이 검증이 새로 여는 질문**(감사자 소관 밖, rev3가 답해야 함): 장문 꼬리 워크로드에서는 **모든 인터랙티브 프로덕션 SLO가 물리적으로 도달 불가**이고 도달 가능한 유일한 외부 좌표가 `batch_async (3000, 200)`이다. 그런데 `reports/serving_slo_survey.md` §0은 그 좌표를 *"비인터랙티브 배치 한정"* 이자 **static이 이기는 체제**로 규정해 뒀다. ⇒ *"이 워크로드에서 정책 비교 질문을 물을 수 있는 유일한 운영점이, 정본이 이미 답을 아는 운영점이다"* 는 것 자체가 GPU 0에서 얻어지는 결과이고, rev3는 이것을 산출물로 명명하든지 워크로드 선택을 다시 논해야 한다.
