## 1. 이 캠페인이 존재하는 유일한 이유 — 그리고 ★무엇을 닫지 *못*하는지

R2(§1-32)의 **결정량 ②가 항등식**이라 미확정으로 남았다:

```
SM합 = (108 − D_ttft) + D_itl > 108   ⟺   D_itl > D_ttft
```

`D_ttft`가 **격자 최대 decode arm = d44**였으므로 `D_itl ≤ D_ttft`가 데이터와 무관하게
성립한다(부트스트랩 10000/10000). 재분석으로는 영원히 나오지 않는다 — 격자에 d44보다 큰
decode arm이 **없기** 때문이다.

★**C1 (감사, (a) 필수 — 등재 문구에 강제 동반)**:
> **이 캠페인이 닫는 것은 ②의 *재정식화판*이다.** gate #16과 §1-32의 원문 ②는 **문턱
> 술어**(pass율 argmax) 도너로 정의돼 있는데, 이 캠페인의 1차 결정량은 **같은 확률변수의
> 위치통계량**으로 재정식화된 판본이다(이유 = §4의 절벽). **원문 ②는 gate #16의 이차
> 표적(HI rate를 용량 근처로 하향)까지 가야 닫힌다.** "gate #16을 닫았다"고 쓰지 말 것 —
> 쓸 수 있는 것은 *"②의 위치통계량 판본을 닫았고, 문턱 판본은 rate 축에 남았다"* 뿐이다.

> 가장 개연적인 실패 경로도 여기다: §4의 K2 라우팅이 발화하면(ITL 밴드 질량 79.6–85.3%로

## 3. ★게이트 #40 — 결정량 항등식 사전 점검 (설계보다 먼저)

`S_max`/`S_min` = **realized 검증을 통과해 생존한 arm의 최대/최소 decode SM**
(하드코딩 74/16 아님 — H3가 arm을 버리면 실효값이 바뀐다, C4).

| | `D_ttft = S_max` | `S_min < D_ttft < S_max` | `D_ttft = S_min` |
|---|---|---|---|
| `D_itl = S_max` | `Δ = 0` **강제** | `Δ > 0` 측정됨, **크기는 하한** | `Δ > 0` **강제**(부호 인플레) |
| `D_itl` 내부 | `Δ < 0` **강제** ← R2가 빠진 셀 | **부호·크기 둘 다 데이터** | `Δ ≥ 0` **강제**(부호 인플레) |
| `D_itl = S_min` | `Δ < 0` **강제** | `Δ < 0` 측정됨 | `Δ = 0` **강제** |

**비대칭(설계 근거)**: 상향 절단은 `D_itl`을 아래로만 편향 ⇒ **`Δ>0` 판정은 절단에 보수적**,
**`Δ≤0` 판정은 `D_ttft < S_max`일 때만 해석 가능**.
★**하단 강제 셀(C4-ii, rev1 미선언)**: `D_ttft = S_min`이면 `Δ = D_itl − S_min ≥ 0`이
**대수적으로 강제**되어 이번엔 *긍정* 판정이 부풀려진다. HI에서는 도달 불가(R2가 d44까지
단조 증가)지만 **LO를 1차로 승격하면(§5) 즉시 살아난다** ⇒ 판정 `TRUNCATED_LOW`(§6).

**도달 가능성은 주장이 아니라 실측이다(감사가 무료 근거를 댐)** — 같은 모델·ctx·엔진·
같은 yml로 돈 `g2_0_hard` OB1024 계열(arm당 n=4 부팅):

| g2_0_hard phase B (in2048/o1024 @4) | d34 | d44 | d54 | d64 | d74 |
|---|---|---|---|---|---|
| 중앙 TTFT (ms) | **383±18** | 553±28 | 870±68 | 1863±16 | 5477±1725 |
| 중앙 per-req ITL p95 (ms) | 48.14±0.15 | 42.15±0.03 | 40.46±1.03 | 36.41±0.01 | **33.09±1.12** |
| 달성 처리량 (req/s) | 0.766 | 0.774 | 0.766 | 0.767 | 0.739 |

⇒ **이 기판에서 `D_ttft`(하단/내부) ≠ `D_itl`(상단 경계)인 "측정되는 셀"이 물리적으로
도달 가능함이 이미 실측돼 있다.** sgptv HI 쪽도 처리량 증분이 감속 중이라
(+0.298 → +0.079 → +0.064 req/s, d16→d24→d34→d44) d74 이전 전환이 개연적이다.

### 3-1. ★C13 — "TTFT-pass 순위 = 처리량 순위 8/8"의 지위 (rev1 라벨 교체)

rev1은 이를 *"항등식이 아니라 경험 법칙"* 이라 적었다. **과소 표현이다.** 교체 문구:

> 과부하·폐쇄예산(NP 고정) FCFS 큐에서 중앙 TTFT ≈ backlog/서비스율의 감소함수이므로
> **"TTFT 도너 = 용량 도너"는 이 regime에서 구조적으로 강제에 가깝다.**
> ⇒ **이 일치를 기전의 독립 증거로 인용 금지**(게이트 #9).

**그럼에도 항등식은 아니다** — 반례가 regime 밖에 실재한다: 위 g2_0_hard phase B는 처리량이
**평탄**(0.739–0.774)한데 중앙 TTFT가 383→5477 ms로 **14× 움직인다**(비포화 셀).
따라서 `Δ`는 선험적으로 결정되지 않는다(감사: 게이트 #40 **재발 아님**).

**결과 서술 문구를 미리 고정한다(강제 동반)**: 이 캠페인의 TTFT 축이 재는 것은
*TTFT 선호가 아니라 **용량***이다. ⇒ 등재 문구는
***"ITL이 요구하는 split이 **처리량 최적 split**과 다른가"*** 형태만 쓰고,
§1-20의 기전 언어("TTFT는 prefill SM으로 산다")로 서술하지 않는다.

## 4. Estimand — 정본 라이브러리에서 축자 (새로 정의하지 않는다)

로드 `pdmux_eval.analyze.load_bench_serving_rounds`(**duration 합산**, 게이트 #7) ·
분위수 `percentile`(선형보간) · 술어 `RequestResult.passes`(게이트 #4).

arm `a`, 부팅 `b`, phase ∈ {HI, LO}에서
- `M_ttft(a,b) = median_requests( ttft_ms )`
- `M_itl(a,b)  = median_requests( percentile(token_itl_ms, 0.95) )`

**★1차-A(공동 1차, 경제적 의미가 있는 판본) — 충분점 세금** (감사 C2)

```
S_itl   = min{ decode SM : mean_b M_itl(a,b) ≤ 60 ms }      (ITL이 SLO를 만족하는 최소 decode SM)
D_ttft  = decode SM of argmin_a mean_b M_ttft(a,b)           (= 처리량 최적 split, §3-1)
Δ_SLO   = S_itl − D_ttft        ;    coupling tax ⟺ Δ_SLO > 0
```

**왜 이것이 1차인가**: `Δ`(아래 1차-B)는 *"ITL이 더 좋아지는가"* 를 묻는데,
**SLO를 이미 통과한 뒤의 ITL 개선은 세금이 아니다**(사야 할 이유가 없다) — 감사 C2.
`Δ_SLO`는 *"TTFT 최적 split이 주는 decode SM으로 ITL SLO를 충족할 수 있는가"* 를 묻는다.
SM 합 대수도 동일하다: `(108 − D_ttft) + S_itl > 108 ⟺ S_itl > D_ttft`.
**구조적 편향 없음** — `Δ` 와 달리 자동으로 상단을 향하지 않는다.

**항등식 점검(게이트 #40)**: `S_itl`이 정의되지 않으면(어느 arm도 60 ms 미달성)
`ITL_INFEASIBLE`, 모든 arm이 만족하면 `S_itl = S_min`이라 `Δ_SLO ≤ 0`이 강제되나 이는
**참인 답**이다(세금 없음) ⇒ 판정 `ITL_UNCONSTRAINED`로 별도 선언(§6).

**★필수 민감도(knife-edge, 사전 등재)**: 구 4-arm 격자에서 HI `M_itl(d24) = 60.203±0.177`은
문턱 60 ms **바로 위**(≈1.1 SD)다. ⇒ `S_itl`을 **ITL SLO ∈ {55, 60, 70} ms** 사다리로
반드시 병기하고, 사다리에서 `S_itl`이 움직이면 **크기 인용 금지·부호만**.

**1차-B(절벽 면역 argmin 판본)** — `D_itl = decode SM of argmin_a mean_b M_itl`,
`Δ = D_itl − D_ttft`. §3 표의 대상이 이 양이다. ⚠️감사 C2: 위치통계량은 포화하지 않으므로
`D_itl = S_max`가 사실상 선험일 수 있다 ⇒ **`Δ`만 단독 헤드라인 금지**, 반드시 `Δ_SLO` 병기.

**유도(왜 술어 교체가 아닌가)**: 정본 술어의 pass율은 같은 확률변수(요청별 `ttft_ms`,
요청별 `percentile(token_itl_ms,0.95)`)의 CDF를 문턱에서 평가한 값이다. 문턱 지시함수
대신 **같은 확률변수의 위치통계량**을 쓴 것이며 확률변수 자체는 바뀌지 않는다.
이유는 R2 §3-5 실측 절벽(ITL 임계 55→60 ms에서 pass율 **+71.6~74.8 %p**, ±10% 밴드 질량
**79.6–85.3%**) = 게이트 #6이 금지하는 조건이다.
**감사 판정: 게이트 #35 위반 아님**(손잡이 자체가 바뀌고 이유가 사전 선언되며 구 손잡이를
2차로 병존 — #35의 실패 모드와 정반대). **손실 3건은 §10-9에 등재.**

**2차(§1-20/§1-32와 비교 가능) — 정본 술어 문턱 도너 @ (TTFT 3000 ms, ITL 60 ms)**
`ttft_pass_frac`·`itl_p95_pass_frac`의 argmax. **게이트 #6 라우팅(사전등록)**: 해당 축의
±10% 밴드 질량이 **> 25%**이면 그 축의 문턱 도너는 **진단 전용, 인용 금지**.
★**집계는 `도너 후보 arm 전체에 대한 max`**(감사 C8 — arm별로 7.8% vs 85.3%까지 갈리므로
min/평균으로 집계하면 ITL 축이 잘못 통과한다).

**1차와 2차가 갈리면 그것 자체를 결과로 등재한다.** 어느 쪽도 사후에 고르지 않는다.

## 6. 결정 규칙 (사전등록 분석기가 **전부** 계산 — 게이트 #20)

**도너 식별(순위 규칙 + 크기 규칙, 감사 C7 — "독립 증거 2건"이 아니라 상관 높은 두 조건임을
명시)**: arm `a*`가 도너로 인정되려면 **둘 다** 만족.
1. 4 블록 중 **≥3 블록**에서 argmin,
2. **블록 재표집 부트스트랩**(블록 단위, 10000, seed=1)에서 선택 빈도 **≥80%**.

**판정표(사전 선언 — 아래 전부 등재 가능한 결과다)**

| 판정 | 조건 | 등재 문구 |
|---|---|---|
| `TAX_POSITIVE` | 도너 식별 ∧ `Δ_SLO > 0` (1차-A) | *"coupling tax 존재(≥ Δ_SLO SM). `S_itl = S_max`면 크기는 하한."* |
| `NO_TAX` | 도너 식별 ∧ `Δ_SLO = 0` ∧ `S_min < D_ttft < S_max` | *"처리량 최적 split이 ITL SLO를 정확히 충족 — 세금 없음."* |
| `NEGATIVE_INTERIOR` | 도너 식별 ∧ `Δ_SLO < 0` ∧ 양 도너 내부 | *"처리량 최적 split이 ITL 요구를 **초과** 충족 — 세금 없음, 여유 `-Δ_SLO` SM."* (rev1 미포괄, C4-i) |
| `ITL_UNCONSTRAINED` | 모든 arm이 ITL SLO 충족 (`S_itl = S_min`) | *"이 부하점에서 ITL은 구속하지 않는다."* |
| `ITL_INFEASIBLE` | 어느 arm도 ITL SLO 미충족 | *"`S_itl` 미정의 — 이 부하점에서 ITL SLO는 격자 안에서 달성 불가."* |
| `TRUNCATED` | `D_ttft = S_max` | *"격자가 여전히 상단 절단 — 결정량 ②는 이번에도 미확정."* **"세금 없음"으로 쓰지 않는다.** |
| `TRUNCATED_LOW` | `D_ttft = S_min` | *"하단 절단 — 긍정 방향으로 강제되므로 `Δ>0`을 세금으로 읽지 않는다."* (C4-ii) |
| `ITL_SATURATED` | 도너 미식별 ∧ 상단 arm 간 `M_itl` 최대 격차 **< δ** | *"상단에서 ITL이 포화 — 도너 비식별이 잡음이 아니라 **포화** 때문."* **정보가 있는 음성**(C3) |
| `UNIDENTIFIED` | 위 어디에도 안 걸리는 식별 실패 | *"도너가 식별되지 않는다"*(§1-13 각주 F의 d34/d44 비식별과 같은 종류) |

`TRUNCATED`·`ITL_SATURATED`·`UNIDENTIFIED`는 **실패가 아니라 결과**다 — 게이트 #21의
반대 방향 오류(결과를 실패로 라벨링)도 금지한다.

**★검정력 · δ(감사 C3, 실측 근거)**: 구 격자 HI `M_itl`의 d34→d44 격차는 **0.20 ms**인데

d44 [57.24, 58.75, 59.34, 59.26] — **완전 중첩**). d54–d74가 d44를 **≳1.5–2 ms** 이기지
못하면 K1은 `UNIDENTIFIED`를 뱉는다. ⇒ **δ = 1.0 ms**를 사전 등재(K7)하고
**블록쌍 차분 `M_itl(d44) − M_itl(S_max)`를 1차 부산물로 사전등록**한다.
(반대 방향 근거: g2_0_hard B는 d44→d74에서 **9 ms**를 벌었다 ⇒ 갈릴 수 있다.)

**★사전 선언된 적응 규칙(사후 지정 금지)**:
`UNIDENTIFIED` ∧ 상단 격차 < δ ⇒ **블록 추가 금지**(포화로 확정, `ITL_SATURATED`).
`UNIDENTIFIED` ∧ 상단 격차 ≥ δ ∧ 블록 간 불일치 ⇒ **블록 2개 추가**(그 이상은 금지).

8. **C2 인용정지 (a)(b)와 무관** — 다른 캠페인·다른 격자.
9. ★**추정량 교체의 손실 3건**(감사 (i)): (a) **크기 비교 불가** — 위치통계량은 goodput/오라클
   이득을 낳지 않아 §1-20 "+16%"·§1-32 "+1.67%"에 대응하는 수를 **원리상 산출 못 한다**
   (단 그 크기 대조는 정본이 이미 인용 금지라 실손실은 작다). (b) **도너 불일치 가능** —
   ORACLE §3-4 사다리가 이미 ITL 도너의 임계 의존(55→d34, 60→d44, 70→d24)을 보였다.
   (c) **명제가 SLO-무관으로 바뀐다** ⇒ 그래서 §4의 1차-A(`Δ_SLO`)가 있다.
   ⇒ **2×2 표(추정량 × 격자)를 결과 문서에 사전등재**: PC-C가 "새 추정량 × 구 격자" 칸을
   채우므로, 나머지 칸을 채우면 **격자 확장과 추정량 교체가 동시에 바뀌는 것**(확인 #10의
   완화형)을 분리할 수 있다.

## 12. 2단계 감사(하네스)에 묻는 것 — 단 하나 + 합격 기준 (게이트 #34·#37)

> **질문: 이 하네스가 §4–§7의 규칙을 축자 그대로 실행하는가?**

**GO 기준 3건**
1. **estimand 축자 일치** — §4의 `M_ttft`·`M_itl`·`S_itl`·`Δ`·`Δ_SLO`가 코드에서 정본
   라이브러리 호출로 구현되고, 사전등록 문구와 **한 글자도 다르지 않게** 대응된다.
2. **양성대조 5종(PC-A~PC-E)이 실제로 헤드라인과 같은 함수·kwargs·분기를 탄다**(PC-B가
   서명으로 assert). **PC-D가 7-arm 경로를 실제로 실행한다.**
3. **판정표 9개 결과가 전부 코드에서 도달 가능**하고, 어느 것도 예외/크래시로 빠지지 않는다.

**이 3건 밖의 발견은 NO-GO가 아니라 caveat**로 접수해 하네스 수정 또는 결과 문서 caveat로
라우팅한다.
