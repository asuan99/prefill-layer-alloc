## 1. 死因 3건 — 무엇이 틀렸고 무엇을 고쳤는가

### 1.1 死因 A — 가드가 잘못된 문턱에 걸려 있었다 (`design_g13_stats.py:721`)

rev2는 exact-F 분기를 `MS_B ≤ MS_W`에서 `MEASUREMENT_FAILURE`로 잘랐다. 그러나
`_ub_exact_f`의 상한이 실제로 퇴화하는 조건은

```
theta = ((MS_B/MS_W) / F₀.₀₅ - 1) / m  ≤  0   ⟺   MS_B/MS_W ≤ F₀.₀₅(df_B, df_W)
```

이고 이 격자에서 `F₀.₀₅ < 1`이다 — **(9,20)에서 0.3405 · (15,32)에서 0.4472 ·
(11,96)에서 0.4067**(저장소 자신의 `_f_quantile`로 산출, PC6/PC8로 검증).
⇒ rev2는 `MS_B/MS_W ∈ (0.34, 1.0]` — 상한이 **양수·유한·피복 정상**인 구간 — 을 통째로
"측정 실패"로 버렸다. **멀쩡한 측정을 측정 실패로 라벨링**한 것이며 방법론 게이트 **#21의
역방향 재발**이다.

**수리**: 각 상한을 **자기 퇴화점**에서 가드한다.

| 상한 | 퇴화점 | rev3 가드 | 근거 |
|---|---|---|---|
| Satterthwaite | `MS_B ≤ MS_W` (UB≡0) | ★**현행 유지** | 여기선 F2가 정확히 옳다 — UB≡0은 자동 PASS라 반드시 막아야 한다 |
| exact-F | `MS_B ≤ F₀.₀₅·MS_W` (θ≤0) | **문턱 교체** | 위 대수 |

**효과**(Ha8 k=10·m=3, sb 0.7842, 사전값 0.4112): 가드 발동률 **0.178 → 0.007**.

## 2. 결정량과 밴드

### 2.1 결정 규칙 (사전등록 대상 문구, rev3)

```
1. 추정: 1원 임의효과, sigma_job^2_hat = (MS_B - MS_W)/m.
2. 상한 선택(데이터 무관, 사전등록): Satterthwaite 상한의 시뮬 피복이 사전값 밴드의
   모든 값에서 >= 0.93 이면 Satterthwaite, 아니면 exact-F 피벗.
   Satterthwaite 승수는 사전값 0.5688%에 고정해 등록한다.
3. ★가드(rev3 수리): 각 상한을 자기 퇴화점에서 자른다.
     Satterthwaite : MS_B <= MS_W          -> MEASUREMENT_FAILURE
     exact-F       : MS_B <= F_.05*MS_W    -> MEASUREMENT_FAILURE
   MEASUREMENT_FAILURE는 절대 PASS로 세지 않는다.
4. 판정: 격차 >= 3 x UB95 이면 PASS, 아니면 "underpowered"로 등재.
5. 합격선: 시뮬 P(pass) >= 0.80 AND 시뮬 피복 >= 0.93,
   ★사전값 밴드 3값 전부 AND sigma_boot 밴드의 등록된 점에서.
6. ★MEASUREMENT_FAILURE로 끝나면: "미확정(UNDETERMINED)"으로 등재하고 종료한다.
   추가 블록을 붙이지 않는다. (§2.4)
```

### ★2.2.1 밴드 점 판정 — **`hi_chi2_upper`(11.52 GPU-hr)를 등록한다** (재감사 §D)

rev3 초판은 이 선택을 재감사에 넘겼고, 재감사가 답했다. 근거는 rev3가 **계산하지 않았던**
두 표다.

**각 계획의 붕괴 σ_boot**(worst P(pass)가 0.80 아래로 떨어지는 지점):

| Ha8 계획 | 비용 | **붕괴 σ_boot** |
|---|---|---|
| k=10·m=3 (`lo` 안) | 2.40 | **1.164%** |
| k=12·m=3 (`mid` 안) | 2.88 | **1.652%** |
| k=16·m=6 (`hi` 안) | 7.68 | **3.892%** |

**실제 σ_boot이 다른 곳일 때의 worst P(pass)**:

| 계획 \ 실제 σ_boot | 0.637 | 0.723 | 1.568 | **3.847** |
|---|---|---|---|---|
| k10m3 (총 6.24) | 0.917 | 0.905 | 0.680 | **0.161** |
| k12m3 (총 6.72) | 0.978 | 0.972 | 0.823 | **0.213** |
| **k16m6 (총 11.52)** | 1.000 | 1.000 | 0.990 | **0.808** |

**판정 근거**:
1. σ_boot의 두측 95% CI는 **[0.979%, 3.847%]**. `mid` 안의 붕괴점은 **1.652%** — 점추정
   1.568%에서 **여유 5%**뿐이고 **CI 대부분 구간에서 무너진다.** CI 상단이 진실이면
   6.24/6.72 GPU-hr를 쓰고 P(pass)≈0.16–0.21, 즉 **`UNDETERMINED`로 끝나 게이트는 열린 채
   전액 손실**이다(방법론 게이트 #3의 실패 양식).
2. `hi` 안만 CI 전 구간을 덮는다(붕괴 3.892% > 상단 3.847%). 단측 95%(3.277%)로 완화해도
   최저가는 7.20으로 사실상 같아 **단측/두측 논쟁에 강건**하다.
3. χ² 상단은 오히려 **충분히 보수적이지 않다** — n=6 표본에 off-spec 부팅이 들어 있고
   χ² 구간은 정규성을 가정한다. 두꺼운 꼬리는 상단을 **반보수적**으로 만든다.
4. ★**비대칭**: 설계 prior 과대추정은 **비용만** 손해다(캠페인 자신의 `MS_W`가 σ_boot을
   다시 재므로 추론은 편향되지 않는다). 과소추정은 **캠페인 전체를 무효화**한다.

⇒ **등록 계획**: M8 `k=16·m=3·60 s`(3.84) + Ha8 **`k=16·m=6·60 s`**(7.68) = **11.52 GPU-hr**.
코드 상수 `REGISTERED_SIGMA_BOOT_BAND_POINT` / `REGISTERED_PLAN_*`에 고정했다.

### ★2.2.2 `lo`는 등록 불가 — 그리고 초판의 서술은 거짓이었다 (B4)

★**정정**: rev3 초판은 `lo`를 *"격리된 부팅을 사전등록 필터로 배제한 값"* 이라고 썼다.
**사실이 아니다.** `named_exclusion.excluded`는 **두 부팅**(`blk2`, `blk5`)이고, 둘 다 빼면
σ_boot = **0.7232%**(n=4)이지 0.6373%가 아니다. **blk2만 빼면 σ_boot은 오히려 오른다**
(1.742%). ⇒ `lo`는 필터 적용값이 아니라 **6개 leave-one-out 중 최소 = 가장 낙관적인
데이터 의존 선택**이다. 코드도 고쳤다(하드와이어 문자열 비교 제거, 목록을 실제로 조회).

★**완전한 사전등록 필터를 만들어도 `lo`는 등록 불가**다 — `lo` 계획의 붕괴점 **1.164%** 가
CI 하단(0.979%) 바로 위이기 때문이다. 필터를 진짜로 등록하려면 (i) 문턱을 데이터 이전
관측량에 **숫자로** 고정 · (ii) ratio 구성에 맞게 **양 다리 대칭 적용**(C2-R 목록은 d16
전용이라 이식 불가) · (iii) 배제된 부팅의 **재실행/대체 정책**(없으면 실현 k·m이 계획
아래로 떨어져 검정력이 무너진다 — 초판은 이 항목을 언급조차 안 했다) · (iv) 필터가
함의하는 σ_boot(0.7232%)에서 재시뮬이 필요하다. ⇒ **`lo`는 보고용 민감도로만 남긴다.**

*(부수: 필터 적용값 0.7232%에서도 Ha8 최저가 60 s 계획은 k=10·m=3 = 2.40으로 같아, 이
결함은 **비용 중립**이었다.)*

### 2.3 사전값(σ_job) 밴드 — 무변경, 단 수입 사실을 명시

밴드 3값 `{0.4112, 0.5688, 0.9542}`는 rev2 그대로다. ★**감사 지적 C3 반영**: 세 값 전부가
**T8/Hs8 셀**(`Hs8/b1`, `T8/b1`, `T8/b15`)에서 나오고 **M8/Ha8의 교차-job ratio 셀은 0개**다.
σ_boot이 arm 간 크게 다른 기판에서 σ_job만 arm-무관하다는 것은 **미검증 가정**이며
(교훈 #31), 이 문서는 그것을 **가정으로 명시**한다(`n_indep=1`). 방향은 보수적일 가능성이
높으나(collapsed regime 교락이 밴드를 부풀림) **증명되지 않았다.**

★**비용 동인 서술**(rev2 §3.2의 arm 비교 문장을 대체 — 인용정지 (a) 준수):
- **M8**: 퇴화율 0.000. 비용은 **job 수(k)** 가 정한다. σ_boot 밴드에 **둔감**(전 3점 3.84).
- **Ha8**: 비용은 **σ_boot** 이 정한다(2.40 ↔ 7.68, 3.2배). 퇴화율은 수리 후 0.002–0.038.

*(두 arm을 같은 표에 둔 것은 비용 산정용이며 "어느 arm이 더 시끄러운가"의 진술이 아니다.)*

### 2.4 ★`MEASUREMENT_FAILURE` 분기의 행동 (감사 기준4 FAIL 해소)

rev2는 "사전등록에 미리 적어야 한다"고만 하고 **적지 않았다**. rev3가 적는다:

> **`MEASUREMENT_FAILURE`로 끝나면 그 arm의 결과를 `UNDETERMINED`로 등재하고 종료한다.
> 블록을 추가하지 않는다.**

왜 "추가 블록"이 아닌가: 그 사후 escalation은 **미등록 sequential**이고, 데이터 의존

★**정정(B1, 재감사) — 초판이 든 근거는 stale이었다.** 초판은 이 선택을 *"rev2 §3.3(`seq2`)이

### ★4.1 항등식 3건을 `all_pass`에서 뺐다 (B2, 재감사 — 교훈 #9의 13번째 재발)

rev3 초판이 **반증 불가능한 명제 3건을 대조·자기검사로 계수**했다. 재감사가 잡았다.

|---|---|
| **PC8** `F₀.₀₅ < 1` | `F₀.₀₅(d1,d2)=1/F₀.₉₅(d2,d1)`이고 `F₀.₉₅>1`은 **항상 참** — 어떤 격자에서도 위반 불가. ★rev3가 옆에 쓴 *"어디선가 ≥1이면 수리가 틀린 것"* 도 **거짓**이다(가드 `msb ≤ fq_lo·msw`는 `F₀.₀₅` 크기와 무관하게 정확히 퇴화점). **문장 삭제.** |

### 5-0. ★gate #13 자체를 닫지 못한다 (rev2에서 승계, **사실 1건 정정**)

### 5-1. ★정본 gate #13(1)의 노드·날짜 요건이 미충족이다 (감사 C1, 신설)
