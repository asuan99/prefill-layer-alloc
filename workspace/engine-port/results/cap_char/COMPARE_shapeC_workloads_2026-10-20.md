## 0. shape C의 정의 상태
- shape C = "입력이 길고 출력도 긴 워크로드"는 2026-10-13 연구 감사가 제안한 **이름**이다. 구체적인 길이 값은 **등록되지 않았다**. 그 근거는 "hybrid ctx 항이 의미를 갖는 곳"이라는 산술 추정이었고, claims-auditor가 NOT-YET-SUPPORTED로 판정했다(`../anchor_audit/VERDICT_claimE_first_arrow_2026-10-19.md` 4번).
- 따라서 이 문서는 shape C를 **고정된 정답으로 두지 않는다**. 세 후보가 hybrid 비용 구조의 어느 구간을 자극하는지를 비교한다.

- 셋 다 **서빙 trace가 아니다**. 도착 과정은 어느 경우든 하네스가 부여한다. 그래서 "서빙용 데이터셋이 아니다"는 LongProc만의 약점이 아니다. LongProc만의 약점은 (i) 서빙 선례가 없다, (ii) N이 작다, (iii) 출력 길이가 과제 등급(0.5K/2K/8K)으로 인위적으로 군집해 있다, (iv) 라이선스 미확인이다.
- **출력 강제(`ignore_eos`)의 함의**: 모델 둘(Nano·Llama)을 비교하려면 출력 길이를 강제해야 한다. 자연 EOS를 쓰면 모델마다 출력 길이가 달라져 교락이 생긴다. 강제하면 LongProc의 "자연적인 긴 출력"이라는 장점은 사라진다. 남는 것은 **(입력, 출력) 길이 쌍의 결합 분포**뿐이다. 서빙 비용은 내용이 아니라 길이로 정해지기 때문이다(radix OFF).

## 2. hybrid 비용 구조에서 각 후보가 자극하는 곳 [유도·가설]

공통 비용 항(Nano-9B-v2 기준, 대조 = Llama-3.1-8B):
- **요청당 메모리** s + k·L. s = 136.9 MiB, k = 16 KiB/토큰, L\* ≈ 8.8k [유도]. Llama는 s = 0, k = 128 KiB이고, 요청당 메모리 교차점은 L\_x ≈ 1.2k [유도]이다.
- **생성 중 메모리 증가**: 출력 토큰마다 k만큼 늘어난다. Nano는 16 KiB/토큰, Llama는 128 KiB/토큰이다. **긴 출력에서는 KV 고갈로 인한 retract 위험이 Llama 쪽에서 훨씬 빨리 커진다** [유도]. 다만 hybrid에서 retract가 일어나면 SSM state를 재-prefill해야 해서 회당 비용이 크다(축 지도 E5).
- **decode step의 ctx 의존**: attention 항만 ctx에 비례한다. Nano는 56층 중 attention 4층이라 ctx 기울기가 완만하다. roofline으로 bs 48 기준 7.1k에서 17.6 ms, 16k에서 21.2 ms, 128k에서 65.5 ms다 [유도, running_cap §2]. Llama는 32층 전부가 KV를 읽으므로 기울기가 가파르다 [유도]. 그래서 **긴 출력 동안 ctx가 L\_in에서 L\_in+L\_out으로 커질 때 ITL이 얼마나 변하는지**가 두 모델에서 다를 것으로 예상한다 [가설].
- **prefill**: Nano의 무경합 floor는 16k까지 L에 선형이다(9 ms + 0.111 ms/토큰 × L) [측정, CM-2 CONFIRMED]. 그보다 긴 L에서도 선형인지는 미측정이다. attention 모델은 긴 L에서 이차 항이 커진다 [유도]. lockstep PD-mux에서는 prefill 하나가 길수록 span 정지 횟수가 늘어난다(CM-4·E4).
- **동시 수(Little)**: 출력이 길수록 동시 decode 수가 늘어 cap 또는 메모리가 구속한다. 짧은 L에서는 s가 지배하고, 긴 L에서는 k·L이 지배한다.

| 후보 | 자극하는 구간 | hybrid에서 특히 다를 것으로 예상되는 점 [가설] |
|---|---|---|
| (가) arXiv-Sum × 4k/8k | 입력이 L\*(8.8k) 부근에 모여 있다. 출력 중 ctx가 6.5k에서 10–15k로 이동하며 **요청 하나가 생성 도중 L\*를 건넌다**(state 지배 → KV 지배) | cap 블록 Q-A(짧은 구간 s 지배)의 주 무대다. Llama 대비 요청당 메모리는 이미 L\_x(1.2k)를 넘었으므로 hybrid가 더 많이 수용할 것이다 [유도]. 긴 출력 동안 ITL은 거의 평탄할 것이다. 이미 감사를 거친 인프라를 재사용할 수 있다 |
| (나) LongBench × 강제 | 넓은 L(2k–85k+). **KV 지배 구간과 긴 prefill** | long-ctx 블록 Q-D의 실제 장문 보조로 쓴다. 긴 prefill 하나가 PD-mux에서 HOL·span 정지를 키우는 구간이다(85k 단일 prefill ≈ 9.4 s, 16k 선형을 외삽한 [유도]). 분포가 넓어 ctx 축이 흐려지므로 **표준 셀이 아니라 보조**로 쓴다 |
| (다) LongProc 8K | 입력 4–12k(일부 38k) × 출력 4–8k, 과제별 군집 | 출력을 강제하면 (가)와 같은 구간을 자극한다. 고유한 값은 "입출력이 실제로 함께 긴 과제가 존재한다"는 **동기(motivation) 근거**와, 과제별 길이 쌍을 **shape C 수치의 출처**로 쓸 수 있다는 점이다 |

## 3. 제안 구조 (사용자 질의 "(가)와 (나)를 모두 쓰는 구조" 반영)
- **shape C 표준 셀 = (가)**: 실제 arXiv-Sum 입력에 출력 길이를 고정해 강제한다. 출력 길이 값은 임의로 고르지 않고 **LongProc 8K 등급의 과제별 출력 평균(3.7–7.9k [문헌])을 근거로 4k·8k 두 점**을 등록한다 [제안]. 이렇게 하면 LongProc을 데이터셋으로 쓰지 않으면서 수치 근거로만 쓴다.
- **long-ctx 블록**: 1차는 합성 고정 길이 {32k, 64k, 96k}이고, 보조는 (나) LongBench 장문(> 32k 하위집합)에 출력을 강제한 것이다.
- **(다) LongProc**: 서빙 측정에는 쓰지 않는다. 논문 동기 절과 shape C 수치의 출처로만 인용한다.
- 선행 CPU 작업: (나)와 (다)의 Nano·Llama 토크나이저 길이 분포를 실측한다(arXiv-Sum의 `ARXSUM_STATS`와 같은 방식). 이것으로 표의 [문헌]·미측정 칸을 [측정]으로 바꾼다.

## 4. 주의
- §2의 "hybrid에서 다를 것"은 모두 가설이나 유도값이다. 정본의 "'hybrid는 KV가 작아 배치 여유가 크다' REFUTED"는 L≈1–1.5k 측정점에 한정된 판정이다(CONSENSUS :2834-2835). 이 문서의 긴 L 예측과 충돌하지는 않지만, 실측 전에는 인용하지 않는다.
- 입력 길이 > 16k에서 prefill이 선형인지는 미측정이다. long-ctx 프로브에서 다시 잰다.
- opchar의 "prefill에서 Mamba 비중 66–71%"는 격리 커널 결과라 서빙 근거로 쓰지 않는다.
