## 1. 死因 (수리 = 재설계) — 번호는 rev1 F1–F4에 이어서 F5–F7

### F5. `visits_argmax`는 강제를 제거하지 않고 **이름만 바꿨다** — H arm의 값은 이미 구매된 정본 데이터로 `no`로 결정돼 있다

**(a) 기전 — 컨트롤러는 anchor idx2에서 d44에 도달할 수 없다.**

```
src/multiplex/multiplexing_mixin.py:809-822   # 결정 분기
src/multiplex/multiplexing_mixin.py:740       # _slo_feasible: idx_new >= idx_cur → return True
```

decode-ward 이동은 FEAS 게이트가 **원천적으로 거부하지 않는다**(`:740`). 따라서 d24→d34→d44는
`_dec_slack < _pf_slack ∧ _dec_slack < 0.15`(⟺ TPOT > 51ms)가 d34에서 다시 발화해야만 일어난다.
**정본이 이미 쟀다** — `CONSENSUS.md` §1-10:

> 로그상 `2→3`(d24→d34) **1회** decode-ward 이동 후 prefill-ward 복귀를 **113회 전부 거부**
> ⇒ **d34에 영구 고정 = one-way ratchet**. … 정지 규칙(tpot<51ms)이 **최적점 못 미쳐 발동**

⇒ **방문 집합 = {d24, d34}. d44 미방문(n=9).** rev2 §10이 anchor를 정본 상수(idx2=d24)로 되돌렸으므로
이 궤적이 그대로 재현된다. 정본 argmax는 d44(§1-7 3.220)이므로 **`visits_H = no` ⇒ `CONTROLLER_DEGENERATE`**.
가드 순서(`… → visits → scoring`)상 종결형 차단이므로 **실질 판정에 도달하지 못한다.**

★신규 확증(이번 감사): job 896565 서버 로그가 거울상을 보여 준다 —
`sgptvsrv_bind_rep1_L3H12_896565.log`에 `SLO-FEAS refused idx=4->4 dec_sm=44->34 … refused_total=152`
가 **152건**. anchor=4면 152회 떠나려다 전건 거부, anchor=2면 113회 돌아가려다 전건 거부.
**어느 anchor에서든 컨트롤러는 FEAS 게이트에 못 박힌다.**

**(b) 축이 두 개의 다른 격자를 가로질러 정의됐다 — 구조적 `no`가 존재한다.**

```
results/slo_sched/pdmux_slo.yml        : sm_group_num 7, manual_divisions 5개 → idx 1..5 = d16..d54
results/slo_sched/pdmux_d64.yml,d74.yml: sm_group_num 3, division 1개 (정적 arm 전용)
```

rev2 §5는 정적 격자를 **`d16…d74` 7점**으로 고정했다. 그러나 컨트롤러의 인덱스 집합은
**{d16,d24,d34,d44,d54} 5점**이다. ⇒ Stage 1 argmax가 **d64 또는 d74로 나오면 `visits = no`가
컨트롤러 거동이 아니라 설정 파일 때문에 참**이 된다. 그리고 이것은 가상의 위험이 아니다 —
`CONSENSUS.md` §1-33(G16 7-arm)의 goodput argmax는 **d44 3.7973 vs d64 3.7752 = +0.58%**이고,
정본 자신이 *"'goodput 최적'도 헤드라인 아님"* 이라 등재했다. **δ=3%보다 5배 작은 격차가
`DEGENERATE` 여부를 가른다.**

**(c) 계측기가 틀렸다 — 존재 술어를 1/32 부표본에 물었다.**

rev2 §1 F2: *"산출은 telemetry `runtime_snapshot.stream_index`의 **시간가중 체류분포**"*.
그러나 `visits_argmax`는 **존재 술어**(한 번이라도 방문했는가)이고, 엔진 자신이 그 채널의
맹점을 **측정치로** 주석에 남겼다:

```
src/multiplex/multiplexing_mixin.py:543-551
  The scheduled grid is a pure COUNT subsample of sync calls. … measured on E1/T8/d44,
  prefill was active 4.9% of wall time but only 0.07% of *sampled* snapshots.
```

시간가중은 **비율**의 편향을 고치지 데이터에 없는 방문을 되살리지 못한다(개수가중 vs 시간가중 confound).
★그리고 **정확한 채널이 같은 아티팩트에 이미 있다** — `:833-837`의
`SLO-BIND %d->%d`(전 이동 축자 기록) + `SLO-FEAS refused idx=%d->%d`(거부된 시도 축자 기록).
하네스가 이미 그 로그를 grep한다(`sharegpt_vary_bench.sbatch:76`).
⇒ 등록된 계측기는 **부정확한 쪽**이고, 정확한 쪽은 GPU 0으로 이미 있다.

**⇒ (a)+(b)+(c): rev1 F2의 강제가 제거되지 않았다. `NO_FLIP_BOTH_LOSE`가
`CONTROLLER_DEGENERATE`로 개명됐을 뿐이며, 그 값은 50 job이 바꿀 수 없다.**

confound 대응: **게이트가 항등식**(결정량이 새 데이터와 무관하게 고정) + **개수가중 vs 시간가중**
+ 메모리항목 76(*"파생 필드가 상위가 비면 답을 지운 뒤 그 답을 말하는 걸 금지할 수 있다"*).

재현: `CONSENSUS.md` §1-10 · §1-33 · `multiplexing_mixin.py:740,809-822,833-843,543-551` ·
`pdmux_slo.yml` vs `pdmux_d64.yml` · `grep -c "SLO-FEAS" results/slo_sched/sgptvsrv_bind_rep1_L3H12_896565.log` → **152**.

### F6. anchor를 되돌리면서 **δ=3%를 재도출하지 않았다** — 알려진 효과가 `undecided` 사구간 한복판에 앉는다

rev2 §10은 anchor를 정본 상수로 되돌렸다. 그러면 이 설계의 **유일한 사전 정보**가 그대로 살아난다
(`CONSENSUS.md` §1-7): `Δ̂_H = 3.132 − 3.220 = −0.088 = **−2.73%**`, `sd_diff = √(0.013²+0.019²) = 0.023`.

등록 상수(`tc1_rule_rev2.py:60-69`, `N_REPS=4`, `DELTA_REL=0.03`, `PAIRED=False`, Welch df=6)로
**감사가 직접 계산**:

```
δ      = 0.03 × 3.220 = 0.0966          se = 0.023/√4 = 0.0115      t(6) = 2.447
win      ⟸ Δ̂ ≥ max(δ, t·se) = 0.0966                → False
lose_sig ⟸ Δ̂ ≤ −0.0966                              → False  (Δ̂ = −0.088)
equiv    ⟸ |Δ̂| + t·se < δ  ⟺ |Δ̂| < 0.0684(95%) / 0.0742(90%)  → False
⇒ sign_H = undecided ⇒ INCONCLUSIVE
```

참값이 −0.088이라 가정한 **도달 확률**(감사 재계산):
`P(lose_sig) = 0.227` · `P(equiv, 90%CI) = 0.116` · **`P(undecided → INCONCLUSIVE) ≈ 0.66`**.

⇒ **가드를 다 통과해도 이 캠페인의 최빈 결과는 `INCONCLUSIVE`다.**

★그리고 **§6 설계층 도달가능성 표에 `INCONCLUSIVE` 행이 없다.**
코드의 `SUBSTANTIVE = {FLIP, REVFLIP, BOTHWIN, BOTHLOSE, UNDERPWR, INCONC}`(`:56`) 6개 중
표는 5개만 적고, 대신 차단 라벨 3개(`DEGEN`/`NODISC`/`REALMM`)를 섞었다 — **표의 모집단 정의가
등록되지 않았고, 빠진 하나가 하필 최빈 라벨이다.**
⇒ **합격기준 ④ = 정직하지 않다.** (rev1 B13이 요구한 "설계층" 층위를, 표가 실제로는 못 밟았다.)

부수: F4 수리(`discrim` 축)는 판별력을 **술어 통과율**로만 정의했다. 그러나 F4가 폭로한 실제 문제는
*"두 모델이 임계 대비 같은 판별 구간에 있는가"* 이고, 그 두 번째 축(**결정 문턱 δ 대비 효과 크기**)은
신설되지 않았다. 판별 구간 안에 있어도 δ가 효과보다 크면 판정은 여전히 불가능하다.

confound 대응: **small-n / 검정력** + **metric cliff 계열**(결정이 δ 경계에서 확률적으로 갈림) +
PS게이트 #34 계열(*"결정 규칙 자체를 먼저 감사"*).

재현: `CONSENSUS.md` §1-7 · `tc1_rule_rev2.py:60-69,152-174` · 위 산술(스크립트는 §7-5).

### F7. §7의 세 대조가 **전부 결과와 얽혀 있다** — rev1 B10(b)의 빈 서명 구멍이 닫히지 않고 이동했다

**(1) 짝 음성 서명(`0` 주입)은 1차 분석의 개명이다.** 주입량 0이면 데이터는 실데이터 그대로다.
따라서 *"발화하면 실패"*(§7 3행)는 **"실데이터가 FLIP이면 대조 실패"** 와 논리적으로 같다.
⇒ 이 판본은 **헤드라인 양성 결과를 대조 실패로 사전등록했다.** 반대로 실결과가 널이면 통과하지만
그때는 아무것도 판별하지 못한다(**빈 서명**, PS게이트 #44). 어느 가지든 대조가 성립하지 않는다.

**(2) 치환 검정은 정본 척도에서 공허하게 통과한다.** 감사 시뮬레이션(정본 사전분포
static 3.220±0.013 · dynamic 3.132±0.019, 각 n=4, C(8,4)=70 전수, 2,000 시행):

```
70개 치환 중 win 문턱(max(δ, t·se)=0.0966)을 넘는 개수  : 평균 0.42
발화 permutation이 0개인 시행의 비율                      : 79%
관측된 최대                                                : 2 / 70
```

즉 **8개 값을 어떻게 재배치해도 문턱에 못 미친다** — 귀무 발화율 ≤ α는 추정량이 잘 보정돼서가 아니라
**문턱이 이 데이터 척도에서 도달 불가**해서 통과한다. rev1 B10(b)가 지적한 것(*"n=2라 t가 커서 공허 통과"*)의
**같은 병, 다른 매개변수**다. §7은 비퇴화성 요건(귀무 분포가 실제로 문턱을 넘을 수 있는가)을 등록하지 않았다.

**(3) `+4δ` 양성대조는 H arm의 부호 상태와 교락돼 있다.** `label()`은
`if sH == "undecided" or sT == "undecided": return INCONC`(`:128-129`)를 **FLIP 분기보다 먼저** 평가한다.
F6이 보인 대로 `sign_H = undecided`가 최빈이므로, **T에 무엇을 주입해도 FLIP은 발화하지 않는다.**
양성대조는 기계장치를 검사 대상 데이터와 **독립적으로** 태워야 하는데, 이 설계는 검사 대상의
상태에 종속된다. §7은 *"실패 분기를 등록한다"* 고만 적고 **이 교락 경로를 등록하지 않았다.**

**⇒ 합격기준 ③ = 세 대조 중 (1)은 항등식/빈 서명 양가, (2)는 빈 서명, (3)은 교락. 전부 걸린다.**

재현: rev2 §7 · `tc1_rule_rev2.py:127-139` · 감사 시뮬레이션(§7-5 스크립트).

## 2. 차단 (수리 가능) — B19–B30, rev1 B1–B18에 이어서

**B19 · 계측 체제 변경이 미등록이고, rev2가 인용한 PS게이트 #41을 자기가 위반한다.**
`visits_argmax`(F2 수리)와 realized 체류(`compar`, F1 수리)는 **둘 다 telemetry를 요구**한다
(`multiplexing_mixin.py:509-514` — `PDMUX_TELEMETRY_PATH`가 비면 `_dual_worker_sync`가 즉시 return).
그런데 §10 손잡이 사전등재표(게이트 #19)에 `PDMUX_TELEMETRY_PATH`·`PDMUX_DUAL_WORKER_TRACE_EVERY`·
`PDMUX_TRACE_FORCE_PREFILL`이 **하나도 없다**. 그리고 이 설계의 앵커는 전부 telemetry **OFF**에서 왔다 —
§1-7의 3.220/3.132/0.023(T11–T13 검정력 인증의 입력), §1-10의 궤적, 그리고 **F2 프로브 job 896565
자신**(`f2_verdict_896565.md`: *"telemetry 미설정"*). PS게이트 **#41**은 축자로:
*"telemetry는 공짜 관찰자가 아니다 — 계측 유무가 바뀐 비교를 드리프트/앵커로 쓰지 마라"*
(`observe_scheduler`가 **모든 sync마다** 실행, 비용 `O(waiting_queue + batch)`). rev2는 이 게이트를
§1 B4와 §8-7에서 **두 번 인용**하면서 **모델 간 비교에만** 적용하고 **자기 앵커에는 적용하지 않았다.**

**B20 · B2의 수리가 이웃 좌표로 전파되지 않았다.** `boot`은 모델별 2축이 됐는데(`boot_H`/`boot_T`),
**`cliff`와 `compar`는 여전히 전역 단일 축**이다(`tc1_rule_rev2.py:81-82`). 4셀(2모델×2arm) 중
어디서 난 절벽·불일치인지 표현할 수 없다 — B2가 지적한 바로 그 결함이 두 축에 그대로 남았다.
(**"수리는 국소"의 축 층위 증거.**)

**B21 · B7이 죽인 부류의 무근거 상수가 두 개 신설됐다.** `REALIZED_MAX_GAP=0.15`·`TOKEN_MAX_GAP=0.20`
(`:70-71`)에 유도가 없다. B7은 `MDE_SLACK=2.0`을 *"무근거 상수"* 로 폐기하고 **결정 문턱에서 유도**하라고
요구했는데, 그 규율이 신설 상수에 적용되지 않았다. 실측 이빨 검사:
- `REALIZED_MAX_GAP=0.15`: 정본 §1-25의 decode축 realized 체류 **전 범위가 0.038–0.187**(T8/Ha8).
  전 사다리의 진폭이 0.149다 ⇒ 문턱 0.15는 **사실상 발화 불가** = 이빨 없는 가드.
- `TOKEN_MAX_GAP=0.20`: **감사가 GPU 0으로 실측**(ShareGPT 2,000 대화, 두 tokenizer 오프라인 로드) —
  median input_len 비 Zamba2/Qwen2.5-3B = **1.136**(raw) / **1.163**(sglang식 ctx-4000 필터 후).
  ⇒ 통과하지만 문턱의 **68–82% 지점**이고, 여유는 0.037–0.064뿐이다. **δ=3%를 재려는 설계가
  14–16%의 토큰 부하 비대칭을 통과시킨다.** (부수: 필터 후 표본 수도 1,904 vs 1,859로 달라
  두 arm은 **같은 요청 집합을 받지 않는다** — B16의 median 비 하나로는 통제되지 않는다.)

**B22 · 4상태 `sign`이 코드에 없다 — 합격기준 ② = FAIL.**
`tc1_rule_rev2.py`는 `t_crit`·`win_threshold`·`p_win`·`power_adequate`를 **코드로 고정**하면서,
정작 판정을 내리는 네 상태(`win`/`lose_sig`/`equiv`/`undecided`)의 **판정 함수를 구현하지 않았다.**
`sign_*`는 축의 **열거값**일 뿐이다(`:91-92`). TOST의 **등가 마진**(δ인가 2δ인가)·**alpha**(0.05인가
양측 0.10인가)·**df**가 어디에도 없다. 그런데 §2 branch-B 해석(*"T의 동적도 실제로 진다"*)은
전적으로 `equiv`에 의존한다. ⇒ **TOST 상세 등록 없이 branch-B를 떠받친다.**
★이것은 rev2 §0이 **정확히 고쳐 인용한** `CONSENSUS §3 항목81 / PS게이트 #61`(*"규칙을 산문으로
고정하면 구멍이 난다 — 결정 규칙은 코드로 고정하라"*)을 **신설 결정 상태에 적용하지 않은 것**이다.

**B23 · `visits_argmax`의 "argmax" 정의가 미등록.** 정적 7점 격자의 argmax인가, 컨트롤러가 도달
가능한 5인덱스 집합 내의 argmax인가? 전자면 F5(b)의 구조적 `no`가 생기고, 후자면 `visits`가
동어반복에 가까워진다. **데이터를 본 뒤 어느 쪽으로도 읽을 수 있다** = 사후 자유.

**B24 · B4의 G16 인용 강도가 정본 제한을 넘는다.** rev2는 §1-33을 *"격자 내부성 근거로만"* 인용해
스코프를 좁힌 것은 옳으나, **격자 내부성 자체가 argmax 위치 주장**이고 §1-33은 그 위치를
*"'goodput 최적'도 헤드라인 아님"*(d44 3.7973 vs d64 3.7752, **+0.58%**)이라 명시 등재했다.
δ=3%짜리 규칙이 0.58%짜리 argmax 위치에 `DEGENERATE` 판정을 걸고 있다.

**B25 · 등록 격자 7점 중 2점을 정본 하네스가 거부한다.**
`sharegpt_vary_bench.sbatch:36` `case "$MODE" in d16|d24|d34|d44|d54)` — `d64`/`d74`는
`*) echo "bad MODE"; exit 1`로 떨어진다. §8의 하네스 요건 8항에 **격자 확장이 없다**(B3이
"7점 고정"을 등록했는데 §8 대조표가 그것을 안 받았다).

**B26 · rate 정규화(§3(f))가 anchor 변경 후 재도출되지 않았다.**
등록 부하점 `1.90·C`에서 `_sat_fb`(`:800`)가 상시 참에 가깝고 ⇒ `_hold` ⇒ **anchor로 수렴**;
`0.48·C`에서는 두 slack 다 여유 ⇒ **anchor로 drift**. 즉 rev1 F2 감사가 쓴 삼도논법
(*"양 부하점에서 컨트롤러가 anchor를 안 떠난다"*)은 **anchor를 바꿔도 rate 축에서 그대로 살아 있다**.
rev2 §1 F2는 anchor 좌표만 고치고 이 좌표를 다시 보지 않았다(변수 동시 변경 계열).

**B27 · 설계시점 검정력 인증의 basis가 다르다.** `T11`–`T13`은 `sdH, baseH = 0.023, 3.220`(`:255`)을
쓰는데 그 값은 **rate 3/12** · **mean-ITL 채점**(하네스 `:88` `m=sum(I[i])/len(I[i])`) · **telemetry OFF**에서
왔다. TC1은 **rate 0.48C/1.90C**(§1-33의 달성 처리량 5.5361–5.6096 req/s로 보면 ≈2.7/10.6) ·

**B28 · `discrim` 축이 결합 술어 하나만 본다.** goodput 술어는 `TTFT ≤ 3.0 ∧ mean/p95 ITL ≤ 0.06`
결합인데, 정본이 이미 세 번 낸 진단은 *"어느 다리가 구속하는가"* 다(§1-7 追記, §3 항목89).
통과율이 (0.05,0.95) 안이어도 **한 모델은 TTFT 다리로, 다른 모델은 ITL 다리로** 판별될 수 있고
그러면 두 모델의 estimand가 사실상 다른 양이 된다. arm별·다리별 통과율을 각각 등록해야 한다.

**B29 · F2 프로브 판정서가 자기 최강 증거를 안 적었다(판정은 살아남음).**

그러나 그 근거는 판정서에 **기재되어 있지 않다**. 사전등록 결정규칙에 **liveness 절**

## 5. ★★추가 판정 — `visits_argmax`가 Zamba2 arm을 막는 것은 (a)/(b)/(c) 중 무엇인가

### 판정: **(b) + (c)** 이고, **(a)는 아니다.**

**(a)가 아닌 이유 — "축이 제 일을 한다"면 축은 *새 데이터에서* 무언가를 발견해야 한다.**
여기서 H arm의 축 값은 **이미 구매된 데이터가 결정**한다(§1-10, n=9 + job 896565의 152건 refusal).
50 job은 그 값을 바꿀 수 없다. 그리고 저자가 (a)의 결론으로 제시한
*"이 컨트롤러 계열로는 모델 귀속을 물을 수 없다"* 는 **이미 정본이다** —
`CONSENSUS.md` §1-10이 *"틀린 static으로 수렴 … ratchet이 조기 정지"* 로,
§1-7(HE0)이 *"死因 = positioning + entanglement"* 로 등재했다.
⇒ **이미 소유한 결론을 50 job으로 다시 사는 것**이 된다(메모리항목 77의 거울상:
*"가장 비싼 지출은 GPU가 아니라 안 산 프로브"* → 여기서는 *"이미 산 답을 또 사는 것"*).

**(b)인 이유 — 등록된 형태로는 실질 판정에 도달할 수 없다.**
`visits`는 종결형 차단이고 argmax ∈ {d44, d54, d64, d74}이면 `no`가 강제된다. 정본 argmax는 d44다.
argmax = d34로 나올 때만 통과하는데, d34와 d44의 격차는 **1.5%**(3.171 vs 3.220)로 **δ=3%의 절반**이다.
⇒ **결정 라벨이 자기 문턱보다 작은 max-over-K 추첨으로 갈린다.** 이것은 저자의 사후 자유가 아니라
**노이즈가 차단 라벨을 정하는 구조**이며, 그 자체로 재설계 사유다.

**(c)인 이유 — 정의가 세 방향으로 과도하거나 어긋난다.**
1. **격자 불일치**: 정적 7점 ⊋ 컨트롤러 5인덱스. argmax ∈ {d64,d74}이면 축이 **설정 파일을 재는 것**이지
   컨트롤러를 재는 게 아니다(F5b).
2. **범주 혼동**: 축은 *"퇴화한 컨트롤러"*(아무것도 안 함)와 *"반응하지만 다른 곳에 앉는 컨트롤러"*(=**positioning**)를
   한 라벨로 접는다. 후자는 **HE0가 등재한 死因 그 자체** = 연구 대상이다.
   대상 현상이 나타나면 차단하는 축은, 답을 지운 뒤 답할 수 없다고 선언한다(메모리항목 76).
   ★실증: job 896565에서 컨트롤러는 **152회 이동을 시도**했다. "퇴화"가 아니라 "봉쇄"다.
3. **계측기 오선택**: 존재 술어를 1/32 count 부표본에 물었다(엔진 자신의 측정: 4.9% wall → 0.07% sampled).

### 처방 — 축을 **방문**이 아니라 **시도/봉쇄**로 재정의하고, 계측을 로그로 옮겨라

서버 로그가 이미 세 상태를 완전 분리한다(GPU 0, 신규 계측 0):

```
grep -oE "SLO-BIND [0-9]+->[0-9]+"        # 실제 이동 (전수, 부표본 아님)
grep -cE "SLO-FEAS refused"               # 시도했으나 거부된 이동 (전수)
```

| 관측 | 라벨 | 의미 |
|---|---|---|
| BIND 0건 ∧ FEAS 0건 | `CONTROLLER_DEAD` | **진짜** 차단 사유(계측 실패 포함) |
| BIND 0–소수 ∧ FEAS 다수 | `CONTROLLER_BLOCKED` | 봉쇄 — **차단 아님, 실질 관측**(정본 §1-10·§1-11의 재현) |
| BIND 다수 ∧ argmax 미도달 | `CONTROLLER_MISPOSITIONED` | **연구 대상 그 자체**(HE0 死因) — 차단 아님 |
| argmax 방문 | `CONTROLLER_REACHES` | rev2가 유일하게 통과시키는 세계 |

**그리고 `argmax`의 준거 집합을 컨트롤러 인덱스 집합(1..5)으로 명시 등록**하거나,
정적 격자를 컨트롤러 집합과 **일치**시켜라(d64/d74 제외). 둘 중 하나를 코드 상수로 못 박아야 B23이 닫힌다.

★그러나 **이 처방만으로는 캠페인을 살릴 수 없다** — F6(δ 사구간)과 F7(대조 셋)이 독립적으로 남는다.

   `방문집합 ⊇ {4}` → `F5_REFUTED` / `방문집합 ⊆ {2,3}` → `F5_CONFIRMED` /

   `REALIZED_MAX_GAP`도 §1-25의 0.038–0.187 범위에서 유도하라(0.15는 이빨이 없다).
5. **F6 해소 — δ를 재도출하거나 estimand를 바꿔라.**
   δ=3%는 `CLAUDE.md 게이트 #3`("3% 미만은 헤드라인 아님")에서 온 **보고 규율**이지 이 estimand의
   MDE가 아니다. 알려진 효과가 2.73%이므로 둘 중 하나:
   (i) δ를 유지하고 n을 올려 `equiv` 구간을 효과 아래로 내린다(현재 equiv 상한 2.13–2.31%),
   (ii) **부호가 아니라 연속 Δ의 2×2 model×arm 상호작용 검정**으로 재정식화한다 —
   그러면 사구간이 사라지고 *"모델 간 Δ가 다른가"* 를 직접 묻게 된다(TC1의 본 질문과 더 가깝다).
   ★어느 쪽이든 **§6 표에 `INCONCLUSIVE` 행을 넣고 사전 확률을 적어라.**
6. **F7 해소 — 대조 셋 재설계.**
   (1) 짝 `0` 주입 **폐기** → **귀무 재표집 데이터에 대한 0 주입**으로 교체(실데이터가 아니어야 한다).
   (2) 치환 검정에 **비퇴화성 요건** 등록: *"`+4δ` 주입 하에서 발화 permutation 비율 ≥ 0.5"* 를
       함께 보고하고 미달이면 대조 무효로 선언. (현 상태: 정본 척도에서 79% 시행이 발화 0개.)
   (3) 양성대조를 **`sign_H`와 독립**하게 태워라 — H arm에도 동시에 `lose_sig`가 되도록 주입하거나,
       라벨 함수가 아니라 **부호 추정량 층에서** 검사하라.
7. **B22 해소 (GPU 0)** — `sign()` 판정 함수를 코드로 고정하라: 입력 `(Δ̂, se, df, δ, α, tost_margin)`,
