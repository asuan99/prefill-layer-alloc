## 0. 답하는 질문과 답하지 않는 질문

## 4. 읽기 규칙 (데이터 전 등록)

| # | 규칙 |
|---|---|
| R-1 | 한 쌍·한 도착률의 라벨 [코드 `mo_spec.READING_RULE` 그대로]: SLO 16쌍 중 두 쪽 모두 달성률 ≥ 0.98이거나 ≤ 0.02인 쌍은 정보 없음으로 뺀다. 남은 쌍이 3개 이상일 때, 그 75% 이상이 한 방향으로 0.03 넘게 차이 나고 반대 방향으로 0.03 넘게 차이 나는 쌍이 하나도 없으면 그 방향 우세. 아니면 `SLO_DEPENDENT`. 남은 쌍이 3개 미만이면 `UNINFORMATIVE` |

| R-6 | 최상단 도착률에서 주 SLO 달성률 ≥ 0.9인 조합이 하나라도 있으면 `unsaturated_top`에 싣는다. 이때 고정 규칙은 계산한 선택을 보여 주되 `FIXED` 대신 `USER_DECISION`을 낸다(확장 단 추가 여부 포함, 자동 추가 없음) [코드] |

## 5. 고정 규칙 [코드 `mo_cap_analyze.fix_cap_mem`] — 전수 분기

**(1) 한 arm·한 쌍의 방향** (4단의 R-1 라벨에서, 오류 단 제외):

| 조건 (위에서부터 먼저 맞는 것) | 방향 |
|---|---|
| 높은 쪽 우세 단과 낮은 쪽 우세 단이 함께 있음 | `MIXED` |
| `SLO_DEPENDENT` 단이 2개 이상 | `TRADEOFF` |
| 오류로 빠진 단이 있고, 어느 방향도 2단에 못 미침 | `ERRORS` |
| 높은 쪽 우세 단 ≥ 2 | 올림 |
| 낮은 쪽 우세 단 ≥ 2 | 내림 |
| 그 밖 | 차이 없음 |

**(2) 두 arm 합치기** [결정 2026-11-15]: 두 arm이 **같은 방향**(둘 다 올림 / 둘 다 내림 / 둘 다 차이 없음)일 때만 그 방향. 그 밖은 전부 `USER_DECISION` — 올림과 차이 없음이 섞인 경우, 올림과 내림, `MIXED`·`TRADEOFF`·`ERRORS`가 하나라도 있는 경우, 쌍의 행이 없는 경우(부팅 미완).

**(3) 값 정하기**:

| 단계 | 입력 | 결과 |
|---|---|---|
| 상한 48 → 128 | 올림 | 128로 가고 다음 단계 |
| | 내림 또는 차이 없음(`cap_tie_break` = 낮은 쪽) | 48에서 멈춤 |
| 상한 128 → 256 (128로 간 경우만) | 올림 | 256 |
| | 내림 또는 차이 없음 | 128 |
| 메모리 비율 쌍(상한 48에서) | 상한이 48: 올림 → 0.75, 내림 → 0.6, 차이 없음 → 0.75(`mem_tie_break` = 높은 쪽) | |
| | 상한이 128·256: 올림·차이 없음 → 0.75, 내림 → (0.6, 그 상한)은 측정 안 한 조합 → `USER_DECISION` | |
| KV 풀 하한 | 고른 조합의 부팅 로그 KV 풀 ÷ 상한 < 6,484(arXiv 요약 입력 중앙값, `workloads/manifest_parts/arxiv_summ.json`) 또는 풀 값 없음 | `USER_DECISION` |
| 포화 미도달(R-6) | `unsaturated_top`이 비어 있지 않음 | `USER_DECISION`(선택은 표시) |
| 그 밖 | | `FIXED` |

- 문턱 [결정 2026-11-15]: 방향에 필요한 단 수 2 · 상한 차이 없음 → 낮은 쪽 · 메모리 비율 차이 없음 → 0.75 · 슬롯당 KV 6,484.
- **상한 256은 이 규칙에서 `FIXED`가 될 수 없다** [유도]: (0.75, 256)의 KV 풀 약 54만 ÷ 256 ≈ 2,110 < 6,484. 256이 우세로 나오면 항상 `USER_DECISION`이다. 상한 128은 통과한다(약 166만 ÷ 128 ≈ 13,000 [유도, 부팅 로그 보간]).
- 규칙은 두 arm의 Job을 함께 읽을 때만 값을 낸다(`mo_cap_analyze.py arms`). arm 하나의 Job은 `ONE_ARM_JOB`. 두 Job을 읽을 때 요청·달성률·라벨은 합치거나 다시 계산하지 않는다. 두 Job의 워크로드·격자·seed·단별 요청 수가 다르면 거부한다.

| 볼 것 | 기대 | 어긋나면 |
|---|---|---|
| 메모리 비율 쌍(상한 48) | 두 arm 모두 차이 없음 → 0.75 | 0.75 우세면 KV 풀이 실제 제약, 0.6 우세면 0.75에서 메모리 압박(로그 확인) |
| 상한 128 대 48 | SG mixed는 차이 없음이 유력, PD-mux는 방향 미상(맞교환이면 `TRADEOFF`) | 두 arm이 다르면 `USER_DECISION` — 그 자체가 결과 |
| 상한 256 대 128 | 차이 없음 | 256 우세면 KV 하한으로 반드시 `USER_DECISION` |
| 규칙의 출력 | **가장 유력: `USER_DECISION`**(상한 48 → 128에서 PD-mux는 올림, SG mixed는 차이 없음으로 갈릴 것으로 예보 [추측]). 다음이 tie-break (0.75, 48) | (0.75, 128) `FIXED`는 두 arm 모두 2단 이상 올림일 때만 |

### 7-b. 검출력 예보 [추측 — 사전 사다리 (0.6, 48)·seed 2개·요청 120건 기반, 인용 불가]

- 채택한 격자에서 SG mixed는 1.66(엄격·기본 경계 근처)과 3.03(느슨 경계 근처)이 정보 있는 단으로 예상되고 5.52·10.05는 거의 전부 실패다 → 정보 있는 단 2개, 방향 판정의 최소치와 같다. 한 단이라도 빗나가면 SG mixed는 "차이 없음"이 된다. PD-mux는 3.03·5.52·10.05 세 단이 예상된다.
- 두 arm이 같은 방향이어야 값이 움직이므로(§5-2), SG mixed가 "차이 없음"이면 결과는 기본값이거나 `USER_DECISION`이다.
- sharegpt 출력 평균 약 286토큰에서 동시 요청 수는 도착률 1.2에 약 10개, 2.5에 약 20–27개 [추측] — 상한 48이 실제로 묶이는 부하는 3.03 이상이다.
- 사전 사다리는 셀당 요청 120건이라, 용량을 넘는 단에서 300초 셀이 어떻게 나올지를 잘 예보하지 못한다. 3.03(SG mixed)과 5.52(PD-mux 상한 48)는 처리량 바로 위라 달성률이 급변하는 구간이다.
- TTFT가 묶이지 않는 단에서는 SLO 16쌍이 사실상 ITL 4개 값으로 줄어 R-1의 "3쌍 이상"이 같은 비교의 사본으로 채워질 수 있다.
- **따라서 tie-break로 나온 (0.75, 48)은 "이 측정이 차이를 보지 못했다"로만 읽는다.**

## 9. 확정된 결정 [결정 2026-11-15, 사용자]

워크로드 sharegpt 첫 턴 · 고정 규칙 문턱 4개 · arm별 Job 2개 · 두 arm 같은 방향일 때만 값 이동, 맞교환·불일치는 사용자 결정 · 부분 실패는 미측정으로 남기고 나머지를 읽음 · 앵커 둘째 단 · 한 Job 역순.
도착률 격자 = 두 arm 공통 1.66 · 3.03 · 5.52 · 10.05(arm별 격자 기각) · 측정 창 SV-SG 720분·SV-PM 540분 · SLO를 넘긴 시간초과는 오류가 아닌 SLO 실패.

## 10. 공시·금지 문안

1. 이 측정은 구성 선택이다. "PD-mux가 SG mixed보다 낫다/못하다"를 이 표로 쓰지 않는다. PD-mux arm은 SGLang 공개 PD-mux 구현(D44, non-sticky)이며 MuxWise 논문 시스템과 동일시하지 않는다.
2. tie-break로 정해진 고정값은 "차이 없음"의 증거가 아니며, 상한·메모리 비율이 SLO에 영향이 없다는 문장으로 쓰지 않는다. SG mixed의 "차이 없음"은 정보 있는 단이 부족했다는 뜻일 수 있다. 3.03(SG mixed)·5.52(PD-mux 상한 48)는 용량 바로 위라 쌍 차이가 부팅 간 처리량 차이로 증폭될 수 있다.
3. 조합마다 부팅이 1개라 쌍 차이에는 부팅·시간 효과가 섞여 있다. n = 4는 trace seed 수다. 두 arm은 다른 Job이라 다른 노드·GPU일 수 있다.
4. 고정값은 sharegpt 첫 턴 하나에서 정해졌다. 다른 워크로드에서 최적이라는 문장을 쓰지 않는다. 상한 256은 KV 하한 때문에 이 규칙에서 고정값이 될 수 없다 [유도].
5. 사전 사다리 값은 인용하지 않는다. 사전 사다리는 셀당 요청 120건이라 용량 위 단의 300초 셀 결과를 예보하지 않는다.
