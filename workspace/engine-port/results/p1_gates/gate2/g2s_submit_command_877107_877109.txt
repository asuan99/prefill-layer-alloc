Gate 2-S main campaign -- exact submission commands (experiment-runner, 2026-08-10)
====================================================================================

WHY THIS FILE EXISTS
---------------------
The partition (amd_a100nv_8) rejects any sbatch invocation that does not
explicitly specify CPU options:

    sbatch: error: [Partition: amd_a100nv_8] Job rejected: CPU options must
    be explicitly specified (e.g. --ntasks-per-node, --ntasks, --cpus-per-task)

The committed g2s_run.sbatch (958c467, PREREG_GATE2S_2026-08-09.md rev6) has
no #SBATCH --cpus-per-task / --ntasks-per-node / --nodes directives, so
`sbatch g2s_run.sbatch ...` alone fails outright on this partition -- it
cannot be resubmitted from the committed file without an external CLI
supplement. This file records exactly what was supplied, so a future
resubmission does not have to rediscover this by trial and error.

REASON THE SCRIPT WAS NOT EDITED: 파티션이 CPU 옵션 명시를 강제하므로 sbatch
내부 지시자가 아니라 CLI로 공급했다(2026-08-10). 사전등록 내용이 아니라 SLURM
인프라 요건이며, 스크립트를 수정하지 않은 이유는 실행본과 커밋본을 일치시키기
위함이다.

WORKING DIRECTORY AT SUBMISSION TIME

/scratch/ehmoon/whlee/prefill-layer-alloc/workspace/engine-port/results/p1_gates/gate2

(g2s_run.sbatch uses relative #SBATCH --output=g2s_%j.out / --error=g2s_%j.err

NOTES
------
- CLI-supplied flags (--nodes=1 --ntasks-per-node=1 --cpus-per-task=8 --mem=64G)
  match the values every other campaign script in this directory (g2ctrl_run.sbatch,
  g2det_run.sbatch, g2detB_run.sbatch, g2_run.sbatch, g2ea_*) hardcodes into its
  own #SBATCH header -- this is not a new/arbitrary choice, it is the
  directory-wide convention, just supplied out-of-band here because g2s_run.sbatch
  omits it.
- g2s_run.sbatch itself was NOT modified for this (per coordinator instruction:
  the running job must match the committed file byte-for-byte). The only
  committed-file changes for this campaign are the two pre-submission-approved
  edits (§6.3 item 1 -v fix + §9 artifact-layout note), applied and confirmed
  live in both jobs' logs before this file was written.
- G2S_TAG=<value> is a required positional env var read by g2s_run.sbatch itself
  (`TAG="${G2S_TAG:?...}"`); it is not a CPU/infrastructure workaround, it is
  part of the script's own documented interface (selects model/ctx/backend/rates).
