## ② 합격 기준 6개 판정

### 1. 결정량이 제조되지 않는가 — **FAIL** (X1, X2, X3)

**직접 변이 실행 결과** (`Q1_FRAC`만 바꾸고 자기검사 재실행):

| 변이 | 자기검사 결과 |
|---|---|
| `Q1_FRAC 0.90 → 0.70` | **ALL PASS** |
| `Q1_FRAC 0.90 → 0.60` | **ALL PASS** |
| `Q1_FRAC 0.90 → 0.99` | **ALL PASS** |
| `JOIN_HIGH 0.95 → 0.10` | **ALL PASS** |
| `Q1_FRAC 0.90 → 0.50` | FAIL (T3 `g_q1_floor` n=0) |
| `< floor` → `<= floor` | FAIL (**T5 [REGRESS — 근거 아님]**만) |

★ **0.50에서 잡힌 것은 검출이 아니라 충돌 아티팩트다** — mutant가 0.5를 하드코드해서 문턱이 0.5가 되는 순간 mutant가 no-op이 될 뿐이다. **0.70·0.60·0.99는 전부 통과한다.** 문서 §3의 *"판정 규칙 = 코드(게이트 #66)"* 는 **1차 문턱에 대해 성립하지 않는다.**

`JOIN_HIGH = 0.95`는 `score()`에서 **한 번도 참조되지 않는 죽은 상수**다(grep 확인: 정의 42행뿐). 문서 §3 표는 *"조인율 <0.95 / ≥0.95"* 를 등록 결정량으로 제시하지만, 측정된 조인율 → `replay_low`/`replay_high` 매핑은 **아직 쓰이지 않은 하네스**에 있다.

<a name="x2"></a>**T8 자체는 항등식이 아니다**(3개 DISCRIM 전부 지정 mutant에서 실제로 실패함을 재현 확인). **그러나 문서가 T8에 부여한 능력은 T8에 없다.** 초판 `T6b`("stream_only ⇒ ctx≠distinct")를 복원해 전 mutant에 걸어 본 결과:

```
orig T6b on base rule: True
mutants that break ORIGINAL T6b: ['g_contra']      ← 항등식이 아니다
```

⇒ 초판 T6b는 **항등식이 아니었다**. `g_contra`가 깬다. T8이 잡은 것은 *"검사가 **지정 mutant** 아래서 공허하게 참"* — 즉 **검사↔mutant 짝짓기 실패**이지 항등식이 아니다. 올바른 수리는 지정 mutant를 `g_contra`로 바꾸는 것이었다. 문서 §3·§12는 이를 *"게이트 #9의 17번째 재발을 작성 중 자기 검출"* 로 승격했다 — **감사 도구 자신에 대한 과잉 신뢰**(교훈 #9/#53의 형태: 도구 자신이 항등식이거나 능력이 과장됨).

**판별검사 커버리지 실측**:

```
T4  broken_by = [g_measurement, g_capture, g_l1, g_l2, g_l3]
T6b broken_by = [g_ctx, g_basis]
T7  broken_by = [g_capjoin]
T5  broken_by = []                                  ← 정상 (REGRESS)
어떤 판별검사도 못 잡는 mutant: [g_contra, g_join_none, g_q1, g_q1_floor]
```

★ **12 mutant 중 8개만 판별검사로 덮인다.** 안 덮이는 4개에 **1차 결정량의 분기(`g_q1`)와 그 문턱(`g_q1_floor`)** 이 들어 있다. 문서 §3 line 61의 *"파라메트릭 약화 포함 — 삭제 변이만으론 문턱 완화를 못 잡는다(교훈 #70)"* 는 **파라메트릭 mutant를 넣고도 문턱 완화를 못 잡는** 더 깊은 형태로 재발했다. `T3`의 "load-bearing"은 *"어떤 세계의 라벨을 바꾼다"* 일 뿐 *"등록된 검사가 실패한다"* 가 아니다.

**`T5`는 정말 근거에서 빠졌는가 → 빠졌다**(반증 실패, ⑤-6 참조). 다만 `<`→`<=` 오프바이원을 잡는 **유일한** 검사가 그 T5다 — 문서가 "근거 아님"으로 격리한 검사가 경계의 유일한 보호막이다.

### 2. 실패 모드가 실질 판정으로 오독되는가 — **FAIL** (게이트 #21). 요구된 3개 예시 **전부 흡수 실패**

세 대조(L1/L2/L3)는 **전부 존재(>0) 대조**다. 존재하는 실패는 잡지만 **부분·비대칭 실패는 통과시킨다**.

| 브리프가 지정한 실패 모드 | 규칙의 실제 채점 | 오독 |
|---|---|---|
| **nsys가 붙었는데 export가 부분 성공** / 버퍼 소진 / 후반 절단 | `export_ok=True`, L1·L2·L3 전부 행 있음 → `l4_frac<0.9` → **`PRIMARY_ESTIMAND_UNCONSTRUCTIBLE`** | ★★★ **실질 라벨.** 게다가 **L4가 마지막 다리**라 절단 편향이 정확히 본 조건을 겨눈다 |
| **캡처는 됐는데 replay가 조용히 eager fallback** | 행은 다 나옴(Q1 통과) → `cudaGraphLaunch` 없음 → `join="none"` → **`KSET_NEEDS_TIME_ATTRIBUTION`** | ★★ 프로브 결함이 *"E1-(d) 경로로 이동"* 이라는 **도구 사실**로 등재된다 |
| **green ctx 생성 실패인데 커널은 돈다**(조용한 fallback) | L3에 행이 **나온다**(기본 스트림에서 돎) → 대조 통과 → `ctx="null"`, `stream="match"` → **`KSET_CONSTRUCTIBLE / stream_only`** | ★★★ **최상위 긍정 라벨.** 실증: `World(ctx="null", stream="match", join="replay_high")` → `('KSET_CONSTRUCTIBLE','stream_only')` |

세 번째가 가장 나쁘다: `stream_only` basis는 **green context가 아예 없어도 항상 성립한다**(스트림으로 커널을 묶는 것은 언제나 가능하다). 즉 **긍정 결론을 현상과 무관하게 제조하는 경로**다. `ctx="parent"`(green ctx가 아님)도 같은 라벨로 간다. `realized_sm`은 §2·§9에서 **보고 항목**일 뿐 **판정 분기가 아니다** — 이 저장소가 이미 당한 형태다(**Stage 0 de-confound: "D108 앵커가 실은 16 SM"** ⇒ *pin은 target 아닌 realized로 검증*).

또한 `l4_frac`이 **스칼라**라 "균일 손실"(L2 기대치도 같이 줄어 비율이 상쇄 ⇒ 정상으로 보임, 교훈 #20 "귀무 채택형 게이트는 노이즈를 보상한다")과 "후반 손실"을 **구분할 수 없다**.

### 3. 세계 공간이 전수인가 — **FAIL**. 빠진 축 최소 8개

5. ★★ **`graphNodeId=0` eager row 혼입** — 축 없음 + **행 선택 술어 자체가 미등록**(X6). 부모 E10이 **명시적으로 지목**한 항목이 그대로 남았다

### 4. 각 라벨이 허가하지 않는 것이 정확한가 — **FAIL**

- ★★ **문서 §3 표가 15개 라벨 중 5개를 빠뜨린다.** 자동 대조 결과 `KSET_NOT_ATTRIBUTABLE`(n=24 세계)과 companion 4개(`E1B_UNMEASURED`/`E1B_DEAD`/`E1B_NEEDS_STREAM`/`E1B_ALIVE`)가 문서에 **한 번도 나오지 않는다**. 문서 스스로 *"라벨 11개 전부 도달 가능"* 이라 세면서 표에는 **10개만** 있다. 코드가 정본이지만 **"허가하지 않는 것"은 문서에만 존재**하므로, 이 5개에는 **등록된 제한이 전혀 없다.** 특히 `E1B_DEAD`는 E1-(b) 경로에 대한 **실질 부정**인데 금지 문구가 0건이다.
- ✔ **`PRIMARY_ESTIMAND_UNCONSTRUCTIBLE`은 정말 "종결 아님"으로만 쓰인다** — **반증 실패**(⑤-8).
- ✔ **`basis`는 라벨에 흡수되지 않는다** — `score()`가 `(label, basis)` 튜플을 반환하고 `g_basis` mutant가 붕괴를 잡는다. **반증 실패**(⑤-7).
- ✗ **`KSET_CONSTRUCTIBLE`이 §3 표가 시사하는 것보다 넓다**: OK 8세계 중 **6이 `stream_only`**, 그중 **green ctx가 없는 세계가 포함**된다(X3). 표에는 그 사실이 없다.
- ✗ ★★★ **§10 금지 문장 목록 자체에 오버클레임이 있다**(X8): *"✗ NVTX 선행조건이 사라졌다 — **Q1·Q2b가 실측으로 답한다**"*. A0는 **엔진을 돌리지 않으므로** 그 질문에 답할 수 없다. 오버클레임 방지 목록이 오버클레임을 한다.

### 5. 가격·자유 모수가 정직한가 — **FAIL**

- **"18개 재열거"는 전수가 아니다**(X6). 최소 누락: **행 선택 술어**(분자에 어떤 행이 드는가) · **L2 기대치 산출식**(replay당 노드 수 × 20? 첫 replay 제외? 중앙값?) · **다리 실행 순서**(L4가 마지막인 것이 X5의 편향을 만든다) · **권한/`perf_event_paranoid`/`NVreg_RestrictProfilingToAdminUsers` 축**(X10) · **두 입도 실행의 순서·독립성**. 전신의 *"전수 6개"* 만큼 거짓은 아니지만 **"전수"라는 표기는 유지될 수 없다.**
- **가격에 미지수가 있다**(X9): 인용한 두 선례가 **둘 다 nsys를 돌린 적이 없다**(R0=프로파일러 무, P1=ncu). P1의 `0.032`는 자기 문서의 *"1분55초 + 30초"*(=145 s=**0.0403**)와도 안 맞고, 그 job은 **`--exclusive`**(8-GPU 노드 전유)라 자원 기준으론 최대 **0.32**다 — A0가 §6에서 인용한 *"exclusive면 8× 틀어진다"* 경고가 **자기 가격 앵커에 그대로 적용된다.** 게다가 §8이 `--time=00:20:00`(=**0.33 GPU-hr**)과 `≈0.03–0.05`를 **같은 표에** 올려 **7× 차이 두 가격이 함께 떠 있다.**
- ✔ **`--exclusive` 불필요 주장은 맞다** — **반증 실패**(⑤-4). 단 근거가 **문서층뿐**이고 권한 축이 미등록이다(X10).

### 6. 하네스 없이 규칙층만 통과시켜도 되는가 — **아니오**

§11의 순서(**① 규칙층 감사 → ② 하네스 → ③ 하네스층 감사 → ④ 제출**)는 **옳다**. 그러나 **지금 규칙층에서 못박아야 하는데 빠진 것**이 있다:

- **X1** 조인 문턱 0.95가 코드에 없다 → 하네스가 "무엇을 `replay_high`라 부를지"를 자유롭게 정하게 된다. **문턱은 하네스 이전에 규칙에 있어야 한다.**
- **X6** 행 선택 술어(`graphNodeId≠0` 등)와 L2 기대치 산출식 → 이게 하네스로 내려가면 **결정량의 정의가 하네스 작성자 손에 있게 된다.**
- **X3·X5** green-ness 가드와 절단 가드는 **축이므로 규칙층 사안**이다.
- **X4** companion에 L2g 대조를 넣는 것 — 그 다리는 **이미 사고 있다**(§2·§4: 4 다리를 두 입도로 각각). 채점에 넣기만 하면 된다.

## ④ 차단 상세

### ★★★ X1 — 등록 문턱이 코드에 없다 (`JOIN_HIGH` 死코드 · `Q1_FRAC` 무보호)
`JOIN_HIGH=0.95`는 `score()`에서 **미사용**(0.95→0.10으로 바꿔도 `ALL PASS`). `Q1_FRAC`은 사용되지만 **0.70/0.60/0.99 어느 값으로 바꿔도 `ALL PASS`**. 게이트 #66의 절반 미이행 + 교훈 #70의 심화 재발.
**수리(GPU 0)**: (a) 조인율을 `join_rate: float` 축으로 바꾸고 `JOIN_HIGH`로 비교, 0.95를 정확히 밟는 세계 포함. (b) 두 문턱 각각에 **문턱값 자체를 재선언하는 판별검사**를 등록(예: `T9: UNCONSTR ⟺ frac < 0.90`을 상수 리터럴로 이중 기입해 대조).

### ★★★ X2 — `T8`의 능력이 과장됐고 초판 `T6b` 진단이 틀렸다
초판 T6b는 **항등식이 아니었다**(`g_contra`가 깬다 — 재구성 실증). T8이 검출한 것은 **검사↔지정 mutant 짝짓기 실패**다. 문서가 이를 *"항등식 자기 검출"* 로 서술 ⇒ 다음 작성자가 T8을 항등식 탐지기로 신뢰하게 된다(게이트 #9의 18회차 위험). 부수: **판별검사가 12 mutant 중 8개만 덮고**, 안 덮이는 4개에 `g_q1`·`g_q1_floor`가 있다.
**수리**: §3·§12의 서술을 *"T8은 지정 mutant 아래서 검사가 공허해지는 것을 잡는다"* 로 정정 + `T10: 모든 mutant가 ≥1개 판별검사를 깬다`를 추가(현재 상태에서 **실패해야 한다**).

### ★★★ X3 — green context가 없는 세계가 최상위 긍정 라벨을 받는다
실증: `ctx="null"` 또는 `"parent"` + `stream="match"` + `join="replay_high"` → **`KSET_CONSTRUCTIBLE / stream_only`**. green ctx 생성 실패·조용한 fallback을 표현하는 축이 없고, **L3 대조는 그것을 못 거른다**(fallback이면 L3에 행이 난다). `realized_sm`은 보고 항목일 뿐 분기가 아니다.
**수리**: 축 `green_realized ∈ {matched, mismatched, absent}` 추가(출처: `TARGET_INFO_CUDA_CONTEXT_INFO.isGreenContext`·`numMultiprocessors`·프로브의 `realized_sm`) + **`absent`면 `PROBE_INVALID`**. `stream_only` basis는 **green-ness의 독립 증거가 있을 때만** 허용.

### ★★★ X4 — companion이 부모 감사 E2를 그대로 재발시킨다
`companion()` 축 = `{run_ok, l1g, l4g_rows, l4g_ctx}`. export 축 없음 · capture 축 없음 · **full-GPU graph 대조 없음**. 실증: `GWorld(l1g="ok", l4g_rows="zero")` → **`E1B_DEAD`**. 즉 *"`--cuda-graph-trace=graph`가 **어디서도** whole-graph 행을 못 낸다"* 는 **green-무관 도구 한계**가 *"green ctx 하에서 (b) 경로가 죽었다"* 로 등재된다. `_hdead`는 `run_ok`/`l1g`만 본다.
**수리(공짜)**: 측정은 **이미 graph 입도로도 4 다리를 산다**. `l2g`(full-GPU graph rows) 축을 넣고 `E1B_NODE_ANALOG := l2g == "zero"`(green-무관)로 분기 + capture/export 축 추가.

### ★★★ X5 — 부분 성공·절단이 실질 라벨로 샌다 (게이트 #21)
세 대조가 **존재 대조**뿐이라 부분 export·버퍼 소진·replay 일부 누락이 `l4_frac<0.9` → **`PRIMARY_ESTIMAND_UNCONSTRUCTIBLE`**(실질 라벨)로 간다. **L4가 마지막 다리**라 절단 편향이 본 조건을 겨눈다. 균일 손실은 비율이 상쇄돼 **정상으로 보인다**(교훈 #20).
**수리**: (a) `l4_frac`를 **replay별 행수 벡터**로(20회 각각 기대 노드 수를 채우는가) — "일부 replay 누락"과 "모든 replay가 균일하게 부족"을 가른다. (b) **L4 뒤에 `L2′` 후행 대조**를 붙여 트레이스 후반 손실을 직접 관측. (c) nsys의 손실 경고/`--stats` 요약을 아티팩트에 기록해 `export_ok`를 3분기로.

### ★★★ X8 — A0의 추정량이 선행 등록(P4 / 원 Stage 0 항목 1)의 추정량이 아니다 — **전이 간극 미등록**
- `PER_LAYER_TYPE_SM_RESPONSE_DESIGN_2026-08-11` **§3.B-E5 / §11-P4**: *"nsys `--cuda-graph-trace=node`가 **replay된 sglang decode 그래프**에서 커널 행을 낸다 + 컴퓨트 노드 권한"*, 실행 형태 *"s8 구성 **1셀**"*.

- A0: **엔진 없이 손으로 만든 spin 커널 그래프**.

A0-**음성**은 (거의) 결정적이지만, A0-**양성은 엔진 그래프로 전이되지 않는다** — 노드 수(수 개 vs 수백) · 캡처 경로(sglang `CUDAGraphRunner` + 메모리 풀 + `capture_forward_mode`) · **동시 green ctx/스트림 2개**(`stream_only` basis가 엔진에서 훨씬 약해진다) · node 입도의 *"significant runtime overhead"*(`--help` 실측 인용). 그런데 §10 금지 목록에 **"A0가 통과했으므로 엔진 decode 그래프에서도 난다"가 없고**, 오히려 *"Q1·Q2b가 실측으로 답한다"* 가 **적혀 있다**. 부수: **A1의 등록 내용(K1 + Q3 축소)에도 엔진 기판 Q1/Q2 재측정이 없다** ⇒ A0+A1을 **다 사도** 2026-08-15 Stage 0 항목 1은 **여전히 미구매**다.

## ⑤ 반증 실패 — 감사가 깨려고 했는데 못 깬 것

1. **sha256 일치.** 문서가 지정한 `57241ce6010e32d3…`가 현재 파일과 **일치**. 규칙 정본 고정은 유효하다.
2. ★**§12 변경 이력표의 수치가 전부 실행으로 재현된다.** `8,192 세계` · `라벨 11` · `mutant 12` · `T6 n=24` · `g_capture n=512` · `g_q1_floor n=32` · `companion 32 세계 C1–C4 PASS` — **전부 일치**. **게이트 #67/#70("검증 칸에 예측을 적는 것")의 재발을 찾지 못했다.** 최근 3회 재발한 형태가 이 판본에는 **없다**.
3. ★**`nsys profile --help` 3주장 중 (a)(b)를 축자 확인.**
   - (a) *"If 'node' is selected, node activities will be collected, but CUDA graphs will not be traced as a whole."* — **상호 배타 CONFIRMED**, 문서 인용은 정확하다.
   - (b) launch origin = `host-only`/`host-and-device` = **호스트/디바이스 코드 기원**, 캡처/replay와 무관 — **CONFIRMED**. §4의 *"이것을 E5의 답으로 읽는 것이 저지르기 쉬운 오독"* 이라는 자각도 옳다.
   - ★**문서에 없는 추가 사실 2개(전부 사전등록에 유리)**: launch origin은 **granularity=graph에서만 지원**되고, **기본 granularity는 driver ≥11.7이면 `graph`** ⇒ primary 실행에 `=node`를 **명시한 것은 필수였다**(사전등록이 옳게 했다).
   - ★**권고**: `--help`가 node 입도에 *"may cause significant runtime overhead"* 라고 적는다 — 이것이 **A1의 중단 기준 K1의 1차 성분**인데 A0는 재지 않는다. **프로파일러 없이 같은 프로브를 1회 더 도는 다리**(GPU ≈수십 초)를 붙이면 K1의 프로브층 하한을 **거의 공짜로** 산다. (엔진 K1로 전이 금지.)
4. ★**(c) `--exclusive`·`--constrain=hwperf` 불필요 — 지지된다.** `nsys profile --help`에서 root/paranoid 요구는 `--cpu-core-events` · `--cpuctxsw=system-wide` · `--cuda-event-trace` · `--ftrace` · `--run-as` · `--sample=system-wide`에만 붙고 **`--trace=cuda`에는 없다**. 도구 문서 과잉 독해를 의심했으나 **깨지 못했다** — 단 X10(권한 축 미등록)은 별건.
5. **`--sample=none`·`--cpuctxsw=none` 등록이 의미 있다** — `--help` 확인: target을 launch하면 둘 다 기본이 `process-tree`다. `--gpu-metrics-devices=none`은 이미 기본값이지만 명시 등록은 무해하고 rev8 P5의 결함을 닫는 것이 맞다.
6. **`T5`가 정말 근거에서 빠졌는가 → 빠졌다.** 어떤 mutant도 T5를 깨지 못하고(실측 `broken_by=[]`), `DISCRIM`에 없고, 총평 줄이 *"3 discriminating checks"* 로만 센다. **분리 표기는 정직하다.**
7. **`basis`가 라벨에 흡수되지 않는가 → 흡수되지 않는다.** 튜플 반환 + `g_basis` mutant + `T6b`. 게다가 `T6b`는 `g_ctx`(**진짜 파라메트릭 약화**)도 잡는다 — 처음에 "합성 mutant에만 의존하는 항등식"이라고 의심했으나 **틀렸다**.
8. ★★**`PRIMARY_ESTIMAND_UNCONSTRUCTIBLE`이 "종결"로 쓰이는 경로를 찾지 못했다.** `T4`가 대조 실패 세계에서의 발화를 막고(그리고 `g_l1`에서 실제로 실패함을 T8이 실증), §10이 금지 문장으로 등록하고, **companion이 (b)를 같은 job에서 산다.** **E1은 닫혔다.**
9. ★★★**死因을 찾지 못했다.** 설계 **형태**를 바꿔야 하는 결함을 찾으려 했고 실패했다. X1–X13 전부 국소 수리다. **"死因 없음"이라고 분명히 쓴다.**

> ★ 위 9개는 **"반증 실패 — 단 X1·X3·X4·X5·X8을 닫기 전엔 `GO` 아님"** 으로 읽어야 한다. 반증에 실패했다는 것이 승인이 아니다.

## ⑥ 값어치 판정 — **지금 이 가격에 살 값이 있는가**

**있다. 단 지금 형태로는 아니다.**

1. ★★★ **A0는 재도출이 아니라 지연된 이행이다.** 트랙 자신이 **2026-08-15**에 *"이것이 통과하지 못하면 나머지 전부 무의미하다. **사전등록 전 필수**"*, *"GPU ≈15분, exclusive 불필요"* 라고 등록한 Stage 0 항목 1을 **9일간 사지 않은 채** rev1→rev8 + Stage 0′ + Stage 0″를 썼고, 그 판본들이 규칙층 감사에서 **연속 `NO-GO`**를 받았다. **이 트랙의 가장 비싼 지출은 GPU가 아니라 이 프로브를 안 산 것이다.** ⇒ 이제라도 사는 것은 **높은 값어치**.
2. **초과분은 정당하다** — Q2a/Q2b/대조 3겹/코드 규칙은 과잉 구매가 **아니다**. 원 Stage 0 항목 1은 *"기록되는가"* 만 물었는데, 그 답이 "예"여도 **E5 세계**(필드는 있는데 캡처 시점 launch에만 조인 ⇒ 멤버십 불가)에서는 트랙이 진행 불가다. Q2b는 원 설계가 놓친 것을 **정확히** 메운다. 대조 3겹은 P1(2겹)·`%smid` R0(3겹)이 값을 **이미 입증**했다. **"15분 프로브를 먼저 사고 결정할 일"이 아니다** — 같은 job 안이므로 한계 비용이 사실상 0이다.
3. ★**부족 구매다.** 같은 job에서 (a) **X8이 만든 기판 간극을 상쇄할 등록**(= 원 Stage 0 항목 1은 A1에서 엔진 그래프로 사야 한다는 명시), (b) node 입도 오버헤드(K1 1차 성분, `--help`가 스스로 경고), (c) **`L2′` 후행 대조**(X5) — 셋 다 거의 공짜인데 사지 않는다.
4. **가격**: 등록을 **벽시계 상한 ≤0.33 GPU-hr**로 고치면 값한다. A0-음성은 node 입도 경로 전체를 **싸게** 죽이고, A0-양성은 약하지만 A1을 정당화한다. 실행 예상치(0.03–0.05)는 참고치로만.
5. **결론**: **X1·X3·X4·X5·X8을 닫은 뒤 사라.** 다섯 개 전부 GPU 0이고 **반나절 이내**다. 그 다음 §11의 ② 하네스 → ③ 하네스층 감사 → ④ 제출로 간다. **X4는 이미 사고 있는 다리를 채점에 넣기만 하면 되므로 비용이 0이다.**
