## 2. 결정량의 원시 정의

### 2.1 시계 — 전부 디바이스

```
step k 의 경계 := [ 첫 커널 start_k , 다음 step 첫 커널 start_{k+1} )     # device 타임라인
T_step(k)      := |그 경계|                                               # 스텝 사이 간극 포함
K_set(k)       := 그 경계 안, decode green-ctx 스트림에 launch된 커널 전부
Σkernel_dur(k) := | ⋃_{i ∈ K_set(k)} [start_i, end_i] |
G_dev(k)       := T_step(k) − Σkernel_dur(k)                              # ★판정 입력
G_host(k)      := |NVTX pdmux.decode_step(k)| − T_step(k)                 # 보고 전용
```

★**NVTX의 역할은 라벨링뿐**이다 — 커널을 step 번호에 붙이고 `decode_step_count`로 텔레메트리와
조인한다. `T_step`은 NVTX 길이가 **아니다**(rev4 B1의 死因).
★`G_host`는 **판정에 들어가지 않는다.** 호스트 스텝 오버헤드는 이 설계의 후보 집합 밖이며,
분리 보고하는 이유는 *"`GAP_DOMINATED`의 내용물이 Python 스케줄러일 수 있다"* 는 오귀속을
**구조적으로 차단**하기 위해서다. `G_host`가 크면 §9에 사실로 등재할 뿐 판정하지 않는다.

### 2.2 항등식 가드 (금지 목록)

`Σkernel_dur`을 `T_step`에서 **역산 금지**(차감·나눗셈·어떤 함수로도). 합집합이지 단순 합이
아니다. `G_dev < 0`은 **clamp 금지** — 디바이스 정의에서는 구조적으로 `≥0`이므로 음수는
**타임스탬프 정합 붕괴 신호**이고 그 창을 측정 실패로 기록한다.

### 2.3 명명된 assert와 변이 테스트 (교훈 #53 / 게이트 #50)

| 이름 | 내용 | 변이본(그 이름의 검사에서 FAIL해야 함) |
|---|---|---|
| `A1_UNION_NOT_SUM` | 합집합 계산이 **합성 fixture**(의도적 겹침 구간 포함)에서 단순 합과 다른 값을 낸다 | 합집합 → 단순 합 |
| `A2_NO_BACKSOLVE` | `Σkernel_dur` 산출 함수가 `T_step`을 **어떤 경로로도 읽지 않는다** — 검사 기구 = (1) 순수 함수 시그니처에 `T_step` 부재 (2) 함수 AST에 `T_step` 심볼 부재 (3) 클로저·전역 참조 목록에 부재 | **3개**: 인자로 받는 변이 · 전역에서 읽는 변이 · 클로저로 캡처하는 변이 |
| `A3_NO_CLAMP` | 음수 입력 fixture에서 예외를 던진다(clamp·`max(0,·)` 없음) | clamp 삽입 |
| ★`E1_NO_PREFILL_KERNEL` | 적격 창 안에 **prefill 스트림 그룹 커널이 0개**(§4.1) | prefill 커널을 1개 섞은 fixture가 통과하는 변이 |

**합격 규칙**: 무변이본 **PASS** ∧ 각 변이본이 **명명된 검사에서, 숫자를 산출한 뒤** FAIL
(다른 예외로 죽으면 불합격) ∧ 기대집합이 **정확**(추가 실패 없음).
★**`VACUOUS` 규칙**: 실데이터에서 어떤 assert의 판별 절이 **0회 발화**하면 그 사실을
아티팩트에 `VACUOUS`로 기록하고 **대조로 계수하지 않는다**(rev4 B5의 死因 재발 차단).

## 3. 판정 — 반사실 하나, 스칼라 하나, 문턱 하나

### 3.1 반사실(사전등록) — 정의이지 물리 예측이 아니다

D=44를 기준으로, D=92에서 **커널 시간이 SM에 완전 비례해 줄고 간극은 그대로**인 세계를
기준선으로 삼는다:

```
K_ideal(92) := K(44) · 44/92          # 완전 병렬 축소 (정의)
G_ideal(92) := G_dev(44)              # 간극 불변 (정의)
T_ideal(92) := K_ideal(92) + G_ideal(92)
```

★**이것은 "이렇게 될 것이다"라는 예측이 아니라 "부족분을 어디에 대고 잴 것인가"라는 기준의
선언**이다. 커널이 메모리 바운드라 SM에 안 스케일하는 것이 바로 `KERNEL_DOMINATED` 가설이므로,
그 가설이 참이면 `S_K`가 크게 나온다 — **순환이 아니라 그것이 측정하려는 양**이다.

### 3.2 단일 판정 스칼라

```
S_K := K(92) − K_ideal(92)            # 커널 쪽 부족분
S_G := G_dev(92) − G_ideal(92)        # 간극 쪽 부족분
S   := S_K + S_G  ( = T_step(92) − T_ideal(92) )
s   := S_G / S                        # ★유일한 판정량
```

`S`가 양수일 때만 정의된다(§3.4의 평탄화 게이트가 그것을 보장한다).

| 판정 | 조건 |
|---|---|
| **`GAP_DOMINATED`** | `s`의 95% CI **전체**가 **> 0.5** |
| **`KERNEL_DOMINATED`** | `s`의 95% CI **전체**가 **< 0.5** |
| **`MULTI_CAUSE`** | CI 전체가 **[0.15, 0.85]** 안에 있고 0.5를 포함 — 즉 **양쪽이 유의하게 기여함이 확정**된 경우 |
| **`UNDETERMINED`** | 그 밖 전부(CI가 0.5를 걸치면서 [0.15,0.85]를 벗어남 · 게이트 실패 · 셀 폐기 · `U_infl` 미측정 · `S ≤ 0`) |

★`MULTI_CAUSE`는 **정량 정의를 가진 결과**이지 판정 실패가 아니다(rev4 B2의 사후 판단 우회로 폐쇄).

### 3.3 rev4 반례로 자기검증 (게이트 #40)

rev4를 죽인 반례 `T44=100(K95,G5) → T92=100(K80,G20)`을 rev5 규칙에 넣으면:
`K_ideal(92)=95·44/92=45.43` · `S_K=80−45.43=34.57` · `S_G=20−5=15` · `S=49.57` ·
**`s=0.303 < 0.5` ⇒ `KERNEL_DOMINATED`** — ★**rev4가 틀리게 지목했던 방향이 바로잡힌다.**
(이 검증은 **설계 문서의 검사**이지 데이터 검사가 아니다. 하네스에도 이 fixture를 회귀로 넣는다.)

### 3.4 선행 게이트 — 정본과 같은 통화(국소 ε)로, 서로 다른 문턱

`ε(D₁→D₂) := −ln(T_step(D₂)/T_step(D₁)) / ln(D₂/D₁)`

| 게이트 | 조건 | 정본 예상치와 여유 |
|---|---|---|
| **양성대조** (레버 작동) | `ε(16→44) ≥ 0.40` | 정본 **0.77–0.88**(`CONSENSUS.md:1590`) — 여유 약 2배 |
| **평탄화 존재** | `ε(44→92) ≤ 0.50` | 정본 **0.09–0.35** — 상단에서도 0.15 여유 |

★rev4의 공유 문턱 `0.85`(=`r_T`)가 정본 구간 `r_T∈[0.77,0.94]`를 **정확히 가르던** 문제
(B6)를 이렇게 없앤다: **평탄화 게이트를 정본 상단(0.35)보다 위(0.50)에 두어** 정본이 맞다면
게이트가 통과하고, **틀려서 ε가 0.50을 넘으면** 그건 *"이 워크로드에선 평탄화가 없다"* 는
**보고 가능한 사실**(`UNDETERMINED (NO FLATTENING HERE)`)이지 문턱 사고가 아니다.
⚠️두 게이트 값(0.40 · 0.50)은 **유도되지 않은 자유 모수**다(§3.7).

### 3.5 불확실성 — 부트스트랩 단위와 판정 규칙

- 재표본 단위 = **(부팅, 적격 창)** 2단 부트스트랩(부팅을 복원추출 → 그 부팅의 창을 복원추출).
  ★부팅이 1차 단위인 이유: 이 저장소가 측정한 지배적 분산원이 **부팅 간**이고(S0(a)는 부팅
  **내부** 단조 drift +5.75%도 기록했다), 창끼리는 독립이 아니다.
- `B = 10,000` · seed 고정 · **CI 전체가 문턱 한쪽일 때만 판정**(§3.2).
- ★1차 비교쌍 `(44→92)`는 **서로 다른 부팅**이다(§9-1에 등재). 부팅 내 위치를 고정하고
  (§6) `n=4`로 부팅 간 분산을 추정한다 — **제거가 아니라 정량화**다.

### 3.6 `U_infl` — nsys node 추적의 부풀림

- **정의**: 같은 (arm, D)에서 `--cuda-graph-trace=node`와 `=graph`의 `T_step` 차이(스텝당).
  ★두 모드는 **launch 시점 옵션이라 같은 창에서 못 잰다** ⇒ 이 추정은 **교차-부팅**이며 그
  잡음 바닥은 부팅 간 분산과 같은 자릿수다. 그래서 `U_infl`은 **(arm,D)별로, n=2 부팅쌍**으로
  재고 **CI를 판정에 전파**한다.
- **보정**: `G_corr = G_dev − U_infl` **그리고 분모도** `T_corr = T_step − U_infl`.
  `s`는 보정된 양으로 계산한다.
- ★**`GAP_BELOW_RESOLUTION`**: `G_corr(92) ≤ 0`이면 그 셀을 폐기하지 않고 **이 이름의 결과로
  기록**한다 — 간극이 계측 분해능 아래라는 **정보 있는 음성**이며 `KERNEL_DOMINATED` 방향의
  증거다(rev4 B8: 폐기는 게이트 #21 역방향이었다).

### 3.7 자유 모수 전수 (5개)

`0.40`(양성대조 ε) · `0.50`(평탄화 ε) · `0.5`(`s` 문턱) · `[0.15,0.85]`(`MULTI_CAUSE` 밴드) ·
`10`(셀당 최소 적격 창) — 여기에 `≥20 decode step/창`. 전부 **결과 데이터 이전**에 고정했고,
전부 경계에서 `UNDETERMINED`로 빠진다. ★`0.5`만은 **유도된 값**이다(부족분의 과반이 어디
있는가 = 질문 자체의 정의). 나머지 4개는 유도되지 않았다 — 감사가 다른 값을 지정하면 채택한다.

## 4. 셀 적격 — nsys가 판정하고, 텔레메트리는 교차확인만

### 4.1 적격 창 (cell A, sticky ON)

| # | 조건 | 판정 채널 |
|---|---|---|
| (a) | 창 안에 **prefill 스트림 그룹 커널이 0개** — assert `E1_NO_PREFILL_KERNEL` | ★**nsys 타임라인**(연속 관측) |
| (b) | `decode_running_batch_size > 0`이 창 전체에서 유지 | 텔레메트리 |
| (c) | 길이 **≥ 20 decode step** | nsys |
| (d) | **정상상태**: 창 안에서 `decode_running_batch_size`의 선형 추세 |기울기|·(창 길이)/중앙값 **≤ 0.10** ∧ 큐 깊이 단조 증가 아님 | 텔레메트리 |
| (e) | 교차확인(불일치 시 **창 폐기, 판정 아님**): 텔레메트리에 `prefill_active_batch_size > 0` 스냅샷 0개 | 텔레메트리 |

★**rev4에서 바뀐 핵심**: (a)의 1차 채널이 **텔레메트리 → nsys**로 옮겼다. rev4 B4가 보였듯
텔레메트리 forced 채널은 `split_prefill_batch` 수명 밖(한 이벤트루프 반복 내 시작·종료)
에피소드를 **구조적으로 못 보고**, P6는 *관측된* 분포만 보므로 **생존자 편향**이었다.
nsys는 커널을 **연속 관측**하므로 그 구멍이 닫힌다. 텔레메트리 (e)는 **교차확인으로 강등**.
★**residency 조건은 판정에서 제거**했다 — 코드 불변식이라(`multiplexing_mixin.py:884-891`,
`:911-912`) 실패할 수 없었고, "realized로 판정한다"는 표기만 만들어 냈다(rev4 B4).

### 4.2 realized SM은 **드라이버에서** 받는다

부팅 시 green context 생성 직후 **드라이버 보고 SM 수**를 사이드카에 기록하고
`(prefill_sm, decode_sm) == (108−D, D)`를 assert한다. 불일치면 **그 부팅 폐기**.
★이것이 §1-21(D108 앵커가 실은 16 SM)의 재유입을 막는 유일한 층이다. 텔레메트리
`decode_sms`는 `sm_counts[stream_index]` **설정값**이므로 이 검증에 쓰지 않는다.

### 4.3 폐기 규칙

① 조건 미충족 창은 **폐기**(가까운 쪽 배정 금지) ② (arm,D)별 적격 창 **10개 미만** 또는 총
**400 decode step 미만**이면 그 셀 폐기 ③ 폐기는 **측정 실패**로 기록(게이트 #21) — 결과 아님.

### 4.4 실현 가능성의 근거는 **상한일 뿐**이다

정본 동거 시간분수 d16 1.3% / d44 4.9% / d92 25–40%(`CONSENSUS.md:1384`)는
`concurrent_time_frac`(둘 다 활성)이라 prefill-active∧decode-empty가 빠져 있고, arm(T8)·
워크로드(s8_frontier open-loop)도 다르다 ⇒ *"prefill-부재 98.7/95.1/60–75%"* 는 **주변 상한**
이다. ★정작 필요한 것은 **연속 ≥20 step의 prefill-free 런 길이 분포**이며 **P6가 그것을 처음
잰다**(교훈 #31).

미충족이면 §9에 등재하되 **판정은 계속한다**(rev4는 여기서 캠페인이 통째로 무산될 수 있었다).

## 9. 닫지 **않는** 것

1. ★**1차 비교쌍 `(44→92)`는 교차-부팅이다.** n=4 부트스트랩으로 **정량화**할 뿐 제거하지 않는다.
2. **(ii) 층 직렬 사슬과 (iv) cudagraph 직렬화를 가르지 않는다** — 둘 다 `GAP_DOMINATED`.
3. **`KERNEL_DOMINATED`가 나와도 그 안의 원인((i) wave / (iii) 점유율)은 이 기판에서 측정
   불가**다(P1 판정). 판정은 *"커널 안에 있다"* 에서 멈춘다.
4. **호스트 스텝 오버헤드는 후보가 아니다** — `G_host`는 보고만 하고 판정하지 않는다.
5. **(v) 메모리 동거 간섭 범위 밖**(cell B 없음) ⇒ §1-26 직교화는 **절반만**.
6. ★**hybrid 고유성 미해결**(T8 삭제) · ★**무제약 108 기준점 미해결**(cell D 삭제) —
   rev4에서 뺀 대가를 여기 등재한다.
7. **성능·정책 주장 0건**, HE0·gate #13/#16 전진 0.
8. ★**인용 금지**: `Δ`·`ε`·`r_T` 어느 것도 정본 `r`(`grand_mean_r`) 계열과 **비교하지 않는다** ·
   **C2 인용정지 (a)(arm별 ε·순위)·(b)(깨끗한 셀 CI·"n=4" 표기) 승계** · "3.06 vs 2.91" 금지.
   ⚠️이 설계가 산출하는 `ε`는 **cell A(비동거) 기판의 값**이라 C2의 ε와 같은 이름의 다른 양이다.

> **단일 질문**: *"단일 스칼라 `s`와 반사실 기준선으로 재정식화한 이 설계가, 고-SM 평탄화의

fixture에서 반증 가능**하고 `VACUOUS` 규칙이 그 실패를 숨기지 않을 것 (iv) §3.4 두 게이트가
정본 구간과 **여유를 갖고** 떨어져 있을 것 (v) `U_infl` 보정과 `GAP_BELOW_RESOLUTION`이
편향을 만들지 않을 것 (vi) §9가 과소하지 않을 것 — 특히 12 부팅 전부가 판정에 **실제로**
