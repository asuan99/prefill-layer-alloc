## 2. 왜 이 귀속이 깨끗한가

정본은 ncu error code 9에 **경합 귀속 3건**을 등재해 두었다. 이번 런은 그것을 **한 축으로
좁힌다** — 아래가 **전부 동일**하기 때문이다:

| 통제된 요인 | 값 |
|---|---|
| job · 노드 · 할당 | 886718 · gpu38 · `--exclusive --constrain=hwperf` |
| 권한 | 동일(대조가 성공했으므로 `ERR_NVGPUCTRPERM` 없음 — 886752와 대비) |
| ncu 호출·메트릭·클럭 정책 | 동일(`--clock-control none`) |
| 타깃 스크립트·커널·차원 | 동일(`bf16_matmul dim=4096`) |
| **변인** | ★**커널이 green-context 스트림 위에 있는가**뿐 |

**두 겹의 대조**가 같은 방향을 가리킨다 — (a) **다리 간**: greenctx 실패 / control 성공,
(b) ★**다리 내부**: 같은 프로세스에서 green ctx 밖 커널 성공 / green ctx 위 커널 실패.

### 2.1 그럼에도 단정하지 않는 것

- 관측은 **"green-context 스트림 위 커널의 프로파일링이 실패한다"**이다.
  라벨 `CUPTI × GREEN-CONTEXT`는 하네스가 붙인 이름이며, **그 실패의 내부 기전**
  (CUPTI 비호환인지, 스트림/컨텍스트 처리의 다른 층인지)은 이 프로브가 가르지 않는다.
- **green context 자체는 정상이다** — `realized_sm=16`으로 실현됐고 커널도 실행됐다
  (886752에서는 `DONE`까지 완주). 깨진 것은 **프로파일링**이지 실행이 아니다.
- **스코프**: A100-SXM4-80GB · driver 580.105.08 · ncu **2025.3.1.0** · CUDA 13.0.2 ·
  이 클러스터. **다른 버전·기판으로 이식 금지.**

## 3. 함의

### 3.1 `kernel_mech` rev3의 범위가 정해졌다 (4세션 이월 해소)

rev2 감사가 지정한 GO 경로는 **"문서 수정 8건 + Stage 0′ 4프로브"**였다. P1이
`UNAVAILABLE`이므로 **Stage B는 폐기**되고, Stage B를 대상으로 하던 문서 수정
(메트릭 교체 · 부착 구조 재작성 · 클럭 제어 이관 등 최소 5건)은 **적용 대상이 소멸**한다.
⇒ **rev3는 Stage A 전용으로 재작성**하면 되고, 작업량이 크게 준다.
★이것이 P1을 문서 수정보다 **먼저** 돌린 이유였고, 그 판단이 값을 냈다.

### 3.2 저장소가 오래 인용해온 주석이 **실증**됐다

`_ncu_target.py:68-71`(CUPTI×green-context 비호환)은 지금까지 **코드 작성자의 주장**이었고
정본은 이를 **미확인 리스크로만** 등재했다. 이제 **관측 근거가 생겼다**.
그리고 `:73-74`의 설계 의도(*"ncu profiling always runs at full GPU"*, `sm_count`는
`n_waves = ceil(grid/sm_count)`의 **해석적** 파라미터)는 **선택이 아니라 강제**였음이
드러난다.

⇒ **트리의 wave 수치는 이 기판에서 원리상 측정일 수 없다** — 이는 rev2 감사의 **F1**
(*"`wave_eff`는 ncu 메트릭이 아니다 / 폐기 선언한 수제 유도를 1차 결정량으로 되살렸다"*)을
**독립적으로 뒷받침**한다.

### 3.3 886752(동반 프로브)가 기여한 것

- **배관 스모크**: 타깃·green ctx·ncu attach·로그·판정 로직이 전부 작동함을 미리 확인.
- **권한 축 분리**: non-exclusive는 `ERR_NVGPUCTRPERM`으로 막힌다는 것을 보여, 886718의
  대조 성공(에러 0건)이 **권한 문제가 아님**을 확증하게 했다.
- 부수: 선례 스크립트 `run_ncu_profile.sh:15-17`의 근거 문장("batch면 권한이 열린다")이
  **불충분**함을 실측으로 보였다 — 실제 구분선은 **exclusive(+hwperf)**다.
