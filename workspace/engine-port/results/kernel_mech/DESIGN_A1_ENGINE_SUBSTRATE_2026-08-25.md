## 0. A1이 존재하는 이유 — A0가 **명시적으로** 남긴 구멍

A0는 **엔진 없이 만든 합성 spin-커널 그래프**(노드 5개, green 스트림 1개)를 쟀고, 그 사전등록 §0-1이
**A0-양성은 sglang decode 그래프로 전이되지 않는다**고 미리 등재했다. 차이는 셋이다:
노드 수(**5 vs 수백**) · 캡처 경로(`CUDAGraphRunner` + 메모리 풀 + `capture_forward_mode`) ·
★**동시 green ctx/스트림 2개**(prefill·decode).

⇒ **A1 = 같은 세 질문(Q1·Q2a·Q2b)을 엔진 기판에서 다시 재는 것** + Q3(축소) + K1.

★**A1이 하지 않는 일**: 성능·정책 판정을 **구조적으로 생산하지 않는다**(요청은 보내지만 결정량이
전부 **행 존재·귀속·조인**이다). `kernel_mech` 트랙을 **열지도 닫지도 않는다** — rev7·rev8 차단
(B1–B5·B7 / C1–C10)은 **전부 불변**이다.

## 1. ★ 순환을 피하는 설계 — 독립 채널이 무엇인가

엔진 기판에서 **"분할이 실현됐는가"** 를 nsys의 `greenContextId`로 판정하면 **Q2a와 순환**한다.
★**엔진 telemetry가 독립 채널을 준다**(2026-08-25 기존 아티팩트로 확인):

| `stream_index` | `decode_sms` / `prefill_sms` | 뜻 |
|---|---|---|
| 0 | 0 / 108 | 전부 prefill |
| 2 | 108 / 0 | 전부 decode(**무분할**) |
| ★**1** | ★**44 / 64** | ★**분할 실현** |

⇒ **엔진이 "분할이었다"고 말하고, nsys가 "이 행들이 있다"고 말한다.** 두 채널은 독립이다.
(`multiplexing_mixin.py`의 `stream_index`는 pdmux arbiter가 고른 파티션 인덱스이고 nsys를 모른다.)

## 2. 다리 — A0의 4겹 대조를 엔진 기판으로 이식한다

| 다리 | 엔진 기판에서의 실현 | 역할 |
|---|---|---|
| **E-L1** | 서버 프로세스의 **아무 커널 행** | 양성대조 — nsys가 엔진을 보는가 |
| **E-L2** | `stream_index = 2`(**무분할**) 구간의 decode graph replay | 대조(**green 무관**) + ★**기대 노드 수 정의** |
| **E-L3** | ★**cudagraph-OFF 부팅**의 분할 구간 decode(=eager, green 스트림) | 대조 — green 위 엔진 커널이 보이는가 |
| **E-L4** | ★`stream_index = 1`(**분할 실현**) 구간의 decode graph replay | **본 조건** |
| **E-L2′** | 마지막 분할 창 **이후**의 무분할 replay | 후행 대조(A0 X5/N1) |

★**E-L3에 별도 부팅이 필요한 이유**: cudagraph-ON에서 decode는 **eager로 돌지 않는다**
(`cuda_graph_runner.py:1161`이 `replay()` 하나뿐). 따라서 "green 위 엔진 커널이 보이는가"는
**cudagraph를 끈 부팅**으로만 대조할 수 있다. 이건 A0의 L3가 공짜였던 것과 다른, **엔진 기판의 대가**다.

## 3. ★ 등록 질문

| | 질문 | A0와의 차이 |
|---|---|---|
| **Q1e** | E-L4 구간의 노드 커널 행이 **기대 대비 ≥ `Q1_FRAC`** | 기대치를 **E-L2(무분할)** 에서 측정 |
| **Q2ae** | 그 행의 `greenContextId`가 채워지고 `streamId`가 **decode green 스트림**과 일치 | ★**동시 스트림이 2개**라 A0보다 강한 시험 — prefill 스트림과 갈리는가 |
| **Q2be** | `correlationId`가 **그 replay의 `cudaGraphLaunch`** 와 조인 | 노드 수백 개 규모 |
| ★**Q3(축소)** | **graph-launch RUNTIME row가 decode 스텝 경계를 구분하는가** — 엔진 telemetry `decode_step_count` 증분과 launch 행 수가 **1:1**인가 | ★**E1-(a)의 직접 시험.** 성립하면 **NVTX 선행조건이 불필요**함이 실측된다 |
| **K1** | nsys 오버헤드 — 같은 구성 nsys ON/OFF의 **엔진 telemetry ITL 중앙값 비**(★구간 라벨만: `≈1 / 1.x / ≥2 / ≥10`) | 부모 E8: 타임라인으로 재면 Q3에 순환 |

## 4. ★ 규칙 — **A0의 것을 그대로 쓴다**

`stage0ppp/stage0ppp_a0_rule.py`(`RULE_REV=4`)의 World 축은 **기판 독립**이다
(`l1·l2·l3·l2_post·capture·green·profile·ctx·stream·join_*·l2_join`). ⇒ **Q1e·Q2ae·Q2be는 그 규칙이
그대로 채점한다.** 바뀌는 것은 **어댑터뿐**이다.
★그 규칙은 **규칙층 감사 3회**(X1–X13 / N1–N13 / R1–R10)를 거쳤고 사전등록 §12에 **하드 스톱**이 있다.
**재감사하지 않는다.**

**새로 필요한 규칙**은 둘뿐이다 — **Q3**와 **K1**. 이 둘만 새 규칙 파일로 코드화하고
(전수 열거 + mutant + 판별검사 + `T19` 계열 메타검사), **그것만 규칙층 감사를 받는다.**

## 5. ★ 사전 등재해야 할 중단 규칙 — **분할 창이 드물다**

기존 아티팩트 실측(`g16_blk1_d44_boot1`, 스냅샷 기준): 분할 실현(`stream_index=1`)은
**59,646개 중 130개**뿐이다. 정본 §1-25도 decode-active 시간의 **4–19%** 만 분할이라 등재했다.

⇒ ★★**E-L4의 행이 적은 것은 "Q1e = 아니오"가 아니라 "창이 부족했다"일 수 있다.** 반드시 사전 등재한다:

```
SPLIT_WINDOW_INSUFFICIENT := 엔진 telemetry가 보고한 분할 구간의 decode 스텝 수 < N_min
   ⇒ MEASUREMENT 조건. Q1e를 채점하지 않는다.
```

`N_min`은 **규칙층 감사 전에 코드로 등록**하고, 워크로드는 분할 창을 **의도적으로 만들도록** 고른다
(prefill이 계속 in-flight여야 하므로 decode-only 라운드로는 창이 안 생긴다 — §1-26).

## 6. ★ 이 설계가 **아직 답하지 않는 것**

- `kernel_mech`의 1차 결정량(`G_intra` 등)은 **여전히 미측정**이다. A1은 그 결정량이 **구성 가능한지**만 답한다.
- **E1-(b)**(whole-graph 입도)는 A0에서 이월됐고 A1에서도 **별도 결정**이 필요하다.
- 부모 **E5**(캡처 시점 조인)는 A0에서 관측되지 않았으나 **엔진 기판에서 다시 시험**된다.
