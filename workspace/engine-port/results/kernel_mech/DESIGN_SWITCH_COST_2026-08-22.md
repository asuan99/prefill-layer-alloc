> **자매 설계**다. rev6는 **전환이 없는 창**(cell A: sticky ON·prefill-free)에서 스텝 시간의

> **의존하지 않는다.**

## 0. 한 줄

**PD-mux가 분할을 바꿀 때 치르는 비용(`2× stream drain + stream 전환 + attn backend 교체`)은
이 저장소에서 한 번도 직접 측정된 적이 없다.** 이 설계는 그것을 **부팅 안에서 페어드로**,
**케이던스 레버**로 잰다.

---

## 1. 왜 — 정본의 근거가 전부 간접이다

**코드 사실**(직접 확인). 전환 경로 `src/multiplex/multiplexing_mixin.py:1053-1066`:
```
prefill_stream.synchronize()          # drain 1
decode_stream.synchronize()           # drain 2
set_current_stream_idx(_tgt)
update_decode_attn_backend(_tgt)      # ★attn backend 교체
```
목표 `_tgt`는 **prefill span마다** 평가되고(`:1030-1041`) **바뀔 때만** drain+switch가 일어난다.
전환 이벤트는 텔레메트리에 `split_transition`으로 방출된다(`:416`).

**정본이 가진 근거 3건은 전부 간접이다**: switch 2회 rep가 static 매칭 · `slo(5sw) < bind(21sw)` ·
컨트롤러 CPU = wall의 0.014%. 앞 둘은 **결과 층 arm 비교**, 셋째는 **컨트롤러 CPU**다.
★**drain 자체를 잰 아티팩트는 0건**이다. 즉 *"switch 비용은 HE0의 死因이 아니다"* 는 지금
**추론**이며, 이 설계는 그것을 **숫자를 가진 상한**으로 바꾼다.

---

## 2. ★천장을 먼저 적는다 (이 절을 읽고 동의 못 하면 사지 마라)

1. ★**HE0를 뒤집을 수 없다.** HE0(동적 < best-static)는 **결과 층** 판정(n≥4, 5.4σ)이다.
   `c`가 크게 나와도 동적이 좋아지는 게 아니라 **死因의 귀속이 옮겨질 뿐**이다. 이 설계는
   **설명을 정밀화하지 결론을 바꾸지 않는다.**
2. **경계 진술은 정당하고 정책 진술은 아니다.** `c × switch_count`로 *"전환이 격차의 최대 X%를
   설명한다"* 는 **상한**은 쓸 수 있다. *"그러므로 어떤 정책이 낫다"* 는 **서빙 실증 없이는 금지**
   (방법론 게이트 #1).
3. **호스트가 막아서 생긴 device 유휴**다. `synchronize()`는 호스트 블로킹이므로 *"device stall"*
   이라 쓰지 않는다.
4. **스코프**: 이 arm·이 D·이 워크로드·이 케이던스 범위. `c`가 배치에 의존하면(§6-③) **곱셈 자체가
   금지**된다.

## 3. 결정량

```
경계 k     := 스텝 k의 마지막 커널 end ~ 스텝 k+1의 첫 커널 start      # = rev6의 G_inter
label(k)   := switch | no-switch      (텔레메트리 split_transition을 decode_step_count로 조인)
★c        := E[G_inter | switch] − E[G_inter | no-switch]            # 같은 부팅·같은 블록 안에서
transient(k):= T_step(k+1) − E[T_step | no-switch 직후]              # attn backend 교체 후 과도응답
```

**1차 = `c`**(부팅 내 페어드). **2차 = `transient`**(전환의 *후속* 비용이 있는가).

★**레버(점추정이 아니라 기울기로 잰다)**: 케이던스 `N` ∈ {2, 8, 32}(N 스텝마다 1회 전환)에서
```
스텝당 평균 간극(N)  ≈  base + c / N
```
을 회귀한다. **기울기 = `c`**, **절편 = 전환 없는 바닥값**(rev6 cell A와 교차검증 가능).
★**반증 가능하다**: `1/N`에 선형이 아니면 *"전환 비용은 가산 상수"* 라는 모형이 **틀린 것**이고,
그건 자유 모수가 아니라 **명명된 실패**(`NON_ADDITIVE`)다.

## 4. 설계 (통제 요인 / 변인 요인)

| | 내용 |
|---|---|
| **통제** | 같은 **부팅** · 같은 arm(**Ha8**) · 같은 분할쌍 · 같은 워크로드 · `CONC` 고정 · `L` 고정 · **cudagraph ON**(운영점) · 같은 노드 |
| **변인 (1차)** | **전환 케이던스 `N` ∈ {2, 8, 32}** — 부팅 **안에서** 블록으로 배치하고 **순서 대조균형**(블록 순서를 부팅마다 역전) |
| **변인 (2차)** | **decode 배치 2수준** — `c`가 상수인지 확인용(§6-③) |
| **달라지는 결과** | `G_inter(switch)` vs `G_inter(no-switch)` · 케이던스별 스텝당 평균 간극 · `transient` |
| **진행 가부** | §7 판정 규칙 |

★**부팅 내 페어드가 이 설계의 핵심 강점**이다. 이 저장소의 지배적 잡음은 **부팅 간 분산**인데
(gate #13이 그것 하나에 11.66 GPU-hr를 썼다), 전환/비전환 경계는 **같은 부팅·같은 블록 안에
교대로** 나타나므로 그 잡음이 **상쇄**된다.

### 4.1 ★강제 케이던스는 엔진 변경을 요구한다 (정직하게)

현재 `_tgt`는 `_r2_decide_idx()`(R2 정책) 또는 `_slo_decide_idx()`(SLO 컨트롤러)가 정하고,
**강제 케이던스 노브는 존재하지 않는다**(env 전수 확인: `PDMUX_R2_POLICY`·`PDMUX_R2_FIXED_DSM`·
`PDMUX_SLO_*` 등 어디에도 없음). ⇒ **`PDMUX_R2_POLICY=alternate` + `PDMUX_ALT_EVERY=N`
(디버그 전용 정책)** 를 추가해야 한다.

**비용과 규율**: dev tree 변경 ⇒ **manifest 갱신 + CPU 회귀(`python -m unittest discover`) +
`src/patches/` 미러**, engine-porter 소관. ★**전환 *기전*은 건드리지 않는다** — 새 노브는
**목표 선택만** 바꾸고 drain/전환/backend 교체 경로는 그대로다. 그 불변을 **패치 리뷰의 합격
조건**으로 건다(안 그러면 재는 대상이 바뀐다).

⚠️**컨트롤러 구동 전환을 쓰면 안 된다**: 컨트롤러는 **부하가 변할 때** 전환하므로 *"전환 비용"*
과 *"전환을 촉발한 부하 상태"* 가 **교락**된다(confound #10). 강제 케이던스가 그 교락을 끊는
유일한 방법이다.

### 4.2 전환은 prefill span에서만 평가된다

`_tgt` 평가가 prefill span에 묶여 있으므로 **측정 창은 동거 체제**다(rev6 cell A의 비동거와
정반대). ⇒ **no-switch 대조 경계도 같은 동거 체제**에서 취해야 비교가 성립한다. 강제 케이던스는
그 조건을 자동으로 만든다(같은 블록 안에서 N−1개 비전환 + 1개 전환).

## 5. 하나의 관측을 여러 번 세지 않기 위한 규약

- `c`는 **경계 단위** 추정량이다. 부팅당 경계가 수백 개라도 **독립 반복이 아니다** —
  부트스트랩 1차 단위는 **부팅**, 2차는 **블록**으로 한다(경계는 3차).
- 케이던스 회귀의 관측 단위는 **(부팅, 블록)** 이고, `N`은 블록 속성이다.
- ★**`c`와 `base`를 "두 개의 독립 결과"로 보고하지 않는다** — 같은 회귀의 두 계수다(게이트 #9).

## 7. 판정 규칙 (결과 보기 전 고정)

| 결과 | 조건 |
|---|---|
| **`SWITCH_COST_MEASURED`** | 회귀 기울기 `c`의 95% CI(BCa, 부팅 1차 부트스트랩)가 **0을 배제** ∧ `1/N` 선형성 점검 통과 |
| ★**`NON_ADDITIVE`** | 선형성 점검 실패 — *"전환 비용은 가산 상수"* 모형이 **반증**됐다. 값을 보고하되 `switch_count`에 곱하지 않는다 |
| **`BATCH_DEPENDENT`** | 두 배치 수준의 `c` CI가 겹치지 않음 ⇒ **곱셈 금지**를 결과에 등재 |
| **`BELOW_RESOLUTION`** | CI가 0을 포함하고 상한이 NVTX 오버헤드(P7) 이하 ⇒ *"전환 비용은 이 계측 분해능 아래"*. ★**"0이다"로 쓰지 않는다** |
| **`UNDETERMINED`** | P7 실패 · 케이던스 블록 미달 · 등가 조건 대량 미충족 |

**선형성 점검(사전등록)**: `N ∈ {2,8,32}` 3점으로 `y = base + c·(1/N)` 적합 후 **잔차가 CI 밖**이면
`NON_ADDITIVE`. 3점이라 검정력이 낮음을 인정하고, ★**그래서 판정은 "선형이다"가 아니라
"선형성을 반증하지 못했다"** 로만 쓴다.

**자유 모수 전수 (3개)**: `N={2,8,32}`(케이던스 격자) · `20%`(⑦의 NVTX 오버헤드 중단 문턱) ·
`블록당 최소 경계 수`(값은 P6′에서 실측 후 고정 — **원자료 보기 전에** 박는다).

## 8. 무엇을 사는가

1. ★**추론 → 숫자를 가진 상한**: `c × switch_count`를 정본의 dynamic/static 격차와 견주어
   *"전환이 그 격차의 최대 X%까지만 설명한다"* 는 **경계**를 만든다. 지금은 이 경계가 없다.
2. ★**더 싼 전환의 상금 천장**: BCG 문서가 인용한 `PDMUX_LA_COORD_OPT`(경계 `synchronize()` drain을
   GPU측 `wait_stream` 순서화로 교체) 같은 제안이 나올 때, `c`가 있으면 **돌리기 전에** 최대 이득을
   계산할 수 있다. 이 저장소가 "상금 크기" 논증으로 헛수고를 막아 온 패턴이다.
3. **rev6와의 교차검증**: 케이던스 회귀의 **절편**이 rev6 cell A의 바닥값과 맞아야 한다.
   안 맞으면 둘 중 하나가 틀렸다는 **독립 신호**다.

## 9. 닫지 **않는** 것

1. **HE0 불변**(§2-1). 정책 순위 변경 0건. gate #13/#16 전진 0.
2. **왜 전환이 비싼가**(drain이 기다리는 in-flight 작업의 내용)는 안 묻는다 — `c`의 **크기**만 잰다.
3. ⑤가 실패하면 **drain과 backend 교체를 못 가른다**.
4. **동거 체제 한정**(§4.2). rev6 cell A(비동거)와 **다른 기판**이며 서로 이식 금지.
5. ★**인용 금지**: 여기서 나온 `c`를 정본 `r`(`grand_mean_r`) 계열·C2 인용정지 (a)(b)·
   "3.06 vs 2.91"과 **비교 금지**. `c × switch_count`는 **상한**이지 관측된 손실이 아니다.
6. **`%smid` R0(job 889631)의 결과를 전제로 쓰지 않는다** — R0는 eager census, 이건 cudagraph-ON.

## 11. 감사 의뢰 (게이트 #37)

> **단일 질문**: *"부팅 내 페어드 + 케이던스 레버로 전환 비용 `c`를 재는 이 설계가, 정본이 지금
> **추론으로만** 갖고 있는 '전환 비용은 死因이 아니다'를 **숫자를 가진 상한**으로 바꾸는가?
> 바꾼다면 엔진 패치 2건의 비용에 값하는가?"*

**합격 기준**: (i) `c`가 데이터와 무관하게 특정 값이 되는 극단 사례가 없는가(게이트 #40) —
특히 **케이던스가 부하를 바꾸는 경로**(⑧)가 `c`를 자동으로 만들지 않는가 (ii) 부팅 내 페어드가
주장대로 부팅 분산을 상쇄하는가, 부트스트랩 단위(부팅/블록/경계 3층)가 옳은가 (iii) `1/N` 선형성
점검이 3점에서 **반증력이 있는가**(없으면 그 한계를 문서가 정직하게 적었는가) (iv) `transient`
분리가 `c` 과대추정을 실제로 막는가 (v) §2 천장(HE0 불변·경계 vs 정책)이 충분한가
(vi) §4.1의 엔진 변경 범위가 **재는 대상을 바꾸지 않는다**는 보장이 규칙층에 박혀 있는가.
**그 외 발견은 NO-GO가 아니라 caveat로 접수한다.**
