## 4. 등록 caveat — 결과 문서·정본이 **문자 그대로** 승계할 문장

> **RA4-1 (★최우선 · 사실 정정)** — 사전등록 §6-5의 표제 문장 *"`inference_mode` 가드와 `Mixer2RMSNormGated.forward_native`(bare Parameter, `n_groups != 1`)의 상호작용은 GPU에서 한 번도 실행된 적이 없다"* 는 **거짓이다.** job 907959는 NemotronH-Nano-9B-v2-Base(`n_groups = 8` ⇒ `mixer2_rms_norm_gated.py:109`가 `forward_native`를 강제)이고, 그 job의 **legacy 2 boot(L1·L2)은 `@torch.inference_mode()`로 데코레이트된 `event_loop_pdmux`(`:1239`)에서 돌았다** — 각 56.0 s, decode step 2,604 / 2,634 전부 `cuda graph: True`, `request_errors = 0`, `crash_free = True`, 로그 내 `RuntimeError` **0줄**. 따라서 이 조합은 **텐서 의미론 수준에서 이미 통과했고**, 새로운 것은 **가드를 든 스레드가 role worker라는 것과 동시성**뿐이다. §11.1의 A908-5 **요약**은 sha 핀 원문의 스코프 `"908020은 …"`을 지운 것이며 **그 요약을 전사 원본으로 쓰면 거짓을 전파한다.**

> **RA4-2 (E5 트리거 계열은 여전히 불완전하다)** — 등록 계열은 설치본(torch 2.9.1+cu130)의 inference-mode 하드 에러 중 **최소 1종을 놓친다**: `RuntimeError: A view was created in inference mode and is being modified inplace in normal mode. …` (감사자 재현: `nn.Parameter`의 view를 inference mode 안에서 만들고 밖에서 `add_` ⇒ 발화, 등록 정규식 **불일치**). **"E5가 inference-tensor 예외를 전부 가로챈다"고 쓸 수 없다.** 저비용 교정안(7개 실측 문자열 중 6개 발화, OOM·무관 `RuntimeError`엔 미발화): `RuntimeError.*(?i:inference[ _](tensor|mode))|RuntimeError.*InferenceMode`. 반대 방향은 안전 — 907959의 실제 OOM 원문은 `torch.OutOfMemoryError`라 **진짜 H1 반증이 가로채이지 않는다.**

> **RA4-3 ((9)는 충분조건이지 필요조건이 아니며, 하네스를 보지 않는다)** — `"GPU 0: "` ⇒ git 0줄(**충분**, porcelain 상태문자에 `G` 없음). 역은 거짓. 또한 pathspec이 **`r2_correctness.sbatch`를 포함하지 않으므로** (9)가 참이어도 **`commit=`이 실제로 돈 하네스를 가리킨다는 보장은 없다** — 현 트리가 그 상태다. 그 보장은 오직 §9-3 P6과 C1 (7)(11)이 준다.

> **RA4-4 ("61–68 %"·"23–26 / 38"은 전사 금지)** — 철회가 문서 전역에 적용되지 않았다(`:783`·`:1428` 생존). 서두 ordinal 1–37은 `#new-seq`가 전부 1이라 in-flight 표본을 ordinal에 귀속시킬 수 없으므로 **그 기저율은 오염이 아니라 애초에 식별 불가능**하다. **F-b1 epoch 정의역의 밀도는 907959로 예보되지 않는다.** (감사자 추정, 인용 금지: 스냅샷/prefill-배치 비 L1 12,458/41 ≈ 304, TD1 7,554/39 ≈ 194.)

> **RA4-5 (발행률 "1.45×"는 특정 쌍의 값)** — **L1 222.4 · L2 234.7 · TD1 153.2 · TD2 153.1 /s**. `1.45×`는 **L1/TD1 쌍**이고 boot 극단비는 **234.7/153.1 = 1.53×**다. 결론(순간값 arm 비교 금지)은 더 강해진다.

> **RA4-6 (전방 강제는 84건 중 44건뿐)** — §11.1은 65건 + 전사 의무 2건을 이 회차에 의무화하고 §11.3이 RR-1…19를 추가하지만, RR-14는 다음 회차에 **44건**만 요구한다 ⇒ **NP-1′…NP-10 · NPC-A…J · N-1…13 · A908-1…7 = 40건 무강제**(rev2→rev3 누수와 같은 형태).

> **RA4-7 (게이트 라벨이 닫는 것 — H1과 분리해 적어라)** — §6-5의 검정력 공시는 **H1에 대해서만** 말하며 *"최대 산출은 §10의 스코프 한정 존재 문장 하나"* 는 **게이트 라벨을 포함하지 않는다.** 라벨이 인증하는 것은 승계 문서에만 있다(`newpair_prereg` §2 + NP-1′ + NP-8): **"위 튜플에서 `PDMUX_TRUE_DUAL_WORKER=1` 경로와 legacy 루프가 S층·O층에서 같은 토큰 id를 내고 그동안 cudagraph가 두 arm 모두 켜진 채 유지된다"** 한 문장뿐이며 **성능도 Claim D도 아니고 P2의 필요조건 하나**다. 907100/907456/X1이 닫았던 선결은 **(Zamba2-2.7B, triton) 한정**이므로 이 회차의 `PASS`는 그것을 **새 쌍에서 다시 세우는 것**이지 새 선결을 닫는 것이 아니다. **라벨 문장과 H1 문장을 같은 문단에서 섞어 쓰지 않는다.**

> **RA4-8 (§9-3의 커밋 목록은 stale)** — 11항목 중 **7항목은 이미 커밋**돼 있고(`b2b60e7`/`a9cd8dd`), 반대로 **§0-c가 sha로 핀한 `job_907959/`는 목록에 없고 untracked**다. 커밋 목록은 **감사 시점 `git status`로 재생성**해야 한다(§6).
