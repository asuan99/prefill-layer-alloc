## 4. 정확한 호출 수 14·7과 θ 후보 수(조이는 방향, 교훈 251)
- 계산기 `limits_check`는 K=8에서 `spans_min 4, spans_max 8` — 모든 span이 1요청인 경우를 배제 안 함. 도착 패턴별 θ 후보(d44, 14호출): 전부 2요청 3/호출 → 42; 1,2,2,2,1 2/호출 → 28; 첫 span 1요청이 바닥(2요청 span ⌊(K−1)/2⌋ = 3, 첫 후보 1개 제외 2/호출) — 첫 prefill(약 1.4 s) 동안 나머지 요청이 모두 큐에 쌓이므로 연속 1요청은 직렬 prefill 가정 아래 불가능; 전부 1요청(직렬 admission이 깨지는 경우) 0.
- 결과 의존 여부: 첫 span이 1이냐 2냐는 poll 주기(≈ decode step, τ의 함수)와 HTTP 발송 산포의 경쟁 → n은 τ에 약하게 의존, 그러나 범위 28–42는 20 아래로 안 내려감. n < 20은 전부 1요청 체제에서만, 그 체제는 설정이 결정하는 결정론적 결과 → 같은 수의 재프로브가 같은 결과 반복 → **K가 나오지 않는 무한 루프(liveness, fail-closed)**, 선택 편향 아님. d16(K=18) 바닥 7/호출, 49.
- 반전 없음. 단 "여유 8(40%)"은 동시 발송 가정 위의 예보 → **N2C-56**. 하네스는 "K개 요청을 pacing 없이 한 번에 발송"을 등록하고, 같은 VI 사유가 두 번 연속이면 정지·보고(새 수치 상수 없음).

## 5. 동결 매니페스트·출처
R9-4 구멍(계산기 사후 변경)은 **기계적으로 닫히지 않음**:
1. **자기검사는 항등식(교훈 9)**: 계산기가 자기 sha를 매니페스트와 비교 — 사후에 고친 계산기는 그 비교 줄도 함께 고칠 수 있음. 매니페스트도 경로 인자로 받는 임의 JSON, 동결 커밋 sha 미검사. 잡는 것은 우발적 드리프트뿐(M08·Y08 사살).
2. **probe.json이 원자료에 결속 안 됨**(`tamper.py`): 축약기가 `KAPPA_CENSORED`를 낸 probe.json에서 검열 측정을 지우고 `probe_status`를 OK로 바꾸면 CLI가 **rc 0, seal True, K (22,10)**. 축약기 sha는 그대로 맞음. "출처 자기계산"은 축약기가 sha를 정직하게 쓴다는 것만 보장.
3. 원자료 sha는 축약 시점 바이트를 증명할 뿐 기록 시점 바이트를 증명하지 않음. 마크는 텍스트라 편집 가능, 프로브는 Workspace에서 돌아 `fetch.sh` sha 목록 없음.
4. 동결 목록 완전성: 문언(§14-2 (iii))엔 마크를 쓰는 하네스 코드가 있으나 그 코드는 존재하지 않고 CLI는 두 파일만 대조. 하네스 구현·감사 전엔 동결 자체가 성립 불가(문언 "감사받은 판 = 동결 판"과 일치) — 순서 문제, 모순 아님.
반전 수치 없음(재량 아닌 출처 구멍), 방어선은 "동결 커밋 도구로 원자료에서 K 재계산" → R10-3.

## 7. L_lag 0 허용
**타당**: L_lag는 이제 축약기가 원자료에서 센 개수(`coload_sent` ≤ t_launch < 첫 co span), 0은 정상 관측, "0 = 누락" 모호성은 키·목록 부재 검사가 따로 맡음; 음수는 축약기 경로에서 불가, M12는 손으로 만든 입력에서만 발화하는 방어 코드; R-list 밖 변경 공시 적절. 잔여 효과: L_LAG가 설계 여유 32에서 관측 최대(0 가능)로 바뀌면 `o_ealpha`가 최대 32 토큰 감소 → 본 측정 지연이 프로브 최대를 넘으면 A2 미완결·b 종료 무효(라벨·부호가 아닌 유효 복제 수에 닿는 fail-closed) → **N2C-55**. 추가 조건: 하네스는 `coload_sent`를 첫 요청 발송 **전에** 찍어야 함(늦으면 L_lag 과소, 첫 co span 뒤로 밀리면 W 거부).

## 필수 수리
**동결 전(축약기·계산기·문언 — 수리 뒤 델타 감사)**
- **R10-1 부류 판정 순서**: 측정마다 평가 가능한 모든 검사를 실행하고 가장 심각한 부류 기록(검열 > VD > VI). `delta_l`·`fix_s` 누락은 추출 뒤 평가. `cell_end`·`coload_sent` 누락은 하네스의 `cell_abort <id> <사유>` 마크로만 VI가 될 수 있고 그 외는 VD. 축약기가 `ReduceRejected`가 아닌 예외로 죽는 경우·짝 없는 `load_call`은 부류 등록(원자료 부재만 VI). 크래시가 난 시도에서도 완결된 측정에 검열·VD가 있으면 재프로브 안 함. 시험: S1–S3·S6 상태가 검열 또는 VD, Y01 사살.
- **R10-2 원자료 기준 완전성**: 원자료의 모든 co형 span(`extend_tokens == n_new×8192`)이 정확히 한 마크 셀 안(고아 span이면 VD); 셀 id 유일(중복 VD); d별 셀 수 정확히 14·7, 미달 VD — 단 텔레메트리가 셀 창 전에 끝났으면(boot 사망) VI. 마크 열거 기반 불변식은 "축약기 내부 누락 방지"로 문언 축소. 시험: S4·S5b·S7 거부.

## 신규 caveat (인용 금지 문장, 문자 승계)
- **N2C-52** 프로브 κ는 결속 셀마다 호출별 κ_i의 등가중 중앙값이다(d = 44 14호출, d = 16 7호출). 중앙값보다 큰 쪽 절반 미만의 호출은 축약값을 움직이지 않는다. 합성 예에서 d = 44 14호출 중 7개가 κ 2.4, 7개가 2.0이면 κ 2.2(K (30, 13))이고, 2.4 호출 하나만 빠져도 2.0(K (27, 12))이다. 실행 K를 "프로브의 모든 호출에서 W_co ≥ 128을 보장한다"로 인용하지 않는다.
- **N2C-53** (R10-1…R10-4 미반영 시 적용 — N2C-50의 후속) rev10 축약기의 완전성 불변식은 마크가 열거한 셀 수와 기록 수를 비교하므로 등록 코드에서 항등식이다(변이 M05 등가). 마크에서 빠진 호출, 셀 id 재사용, 호출 수 14·7 미달, 마크 누락에 따른 부류 재배정(검열·값 의존 → 값 무관)을 잡지 못했다. 계산기는 probe.json을 원자료와 재대조하지 않아, 사후 편집된 probe.json(검열 측정 삭제 + 상태 OK)이 봉인 허용을 받았다. 감사 rev10 추가 변이 14종 중 10종(상태 우선순위 값 의존/값 무관, 짝수 n 중앙값, τ 창 A1/A2 포함)이 생존했다. 이 판의 축약기·계산기를 측정 완전성·출처 진정성·재프로브 분류 정합성의 근거로 인용하지 않는다.
- **N2C-54** `KAPPA_CENSORED`는 C(= W_co ∩ bs = b ∧ in-flight ∧ PAIR[d]) < 128의 기록이며, W_co 자체의 짧음(큰 κ)과 동거 필터 손실(bs ≠ b, 실현 쌍 불일치, 비-in-flight)을 구별하지 않는다. W_co와 필터 손실 분해 없이 검열 보고를 "κ가 프로브 측정 상한 κ\*를 넘는다"로 인용하지 않는다.
- **N2C-55** rev10부터 L_lag는 프로브 호출에서 원자료로 센 최대 iteration 수이며(0 가능), 설계 여유 32를 대체한다. 본 측정에서 이를 넘는 지연은 E-α 출력 길이 여유를 줄여 A2 미완결·b 종료 무효로 나타난다. 그 무효율을 동거 감속이나 ρ의 결과로 인용하지 않는다.
- **N2C-56** θ 표본 수 n ≥ 20의 여유(d = 44 28, d = 16 49)는 co-load K개 요청이 한 번에 발송되어 첫 span 뒤 2요청 span으로 묶인다는 도착 가정에 근거한 예보다. 계산기의 span 검사는 전부 1요청 span(spans_max = K)을 배제하지 않으며, 그 경우 n = 0이다. 프로브 θ의 표본 수를 "구조적으로 보장된다"로 인용하지 않는다.
