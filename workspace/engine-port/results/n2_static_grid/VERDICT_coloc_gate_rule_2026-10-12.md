# 판정서 — Job-EA 동거 비중 관문 판단 규칙 초안 r1 감사 (claims-auditor, 2026-10-12, 규칙층, 읽기 전용)

> 저장: 메인 세션(2026-10-12). 대상 `DECISION_RULE_coloc_gate_2026-10-12.md` draft r1. 본문 요지는 감사 보고 그대로(서식 정리).

## 0. 판정: `NO-GO` — 死因 2건 (D-1 N4 반전 수치 있음, D-2 N1)
감사자 노출 공시: f는 계산하지 않았으나 `RESULT_n3_B_r3_2026-10-06.md` §7의 3회차 rate 0.10·0.15 CO-a(wall 분모) seed 평균 2개를 의도치 않게 봤다 — 어느 판정에도 쓰지 않았고, R-7(블라인드 전제 붕괴)의 직접 증거다.

### D-1 (N4, 반전 확인): STOP이 성분 측정 f와 가정값 Δ로 정책 효과를 주장하며, 상한이 등록·감사 수치로 깨진다
게이트 3의 3%는 판정 지표(goodput·용량) 차이 문턱이지 decode step 시간 문턱이 아니다. f×Δ < 3%가 지표 차이 < 3%를 뜻하지 않는 경로 셋:
1. metric cliff — N3C-6: 3% 안 ITL 섭동이 offered 3.0에서 ITL 통과율 1.000→0.490; HE0 감사: token ITL p95 +0.35%가 60 ms 술어에서 goodput −34%. k=3 용량 셀은 정의상 절벽(1요청 차).
2. 요청 내부 p95는 시간 비율로 희석되지 않는다(게이트 4) — shape B 출력 64토큰, p95 ≈ 위에서 4번째; span 하나가 decode iteration ≈37개(κ 1.3–1.6 적용 ≈23–29) 덮음 ≫ 4 → 노출 요청이 받는 효과는 f×Δ가 아니라 Δ 자체(τ-B Δ 0.20이면 3%의 6.7배).
3. 결속 술어가 decode가 아니다 — shape B 구속은 TTFT(N3 §10-2, ITL 여유 1.75배); 재배분은 prefill SM(64↔74/84/92)을 바꿔 대기열(1/(1−ρ))로 동거 시간 밖 TTFT까지 번진다(entanglement 기전). decode 분모 f×Δ는 이 경로를 덮지 않는다.

### D-2 (N1, estimand 부재): f는 "Job-EA의 검출력"도 "재배분 효과의 상한"도 아니다
- Job-EA는 동거를 강제로 만든다(K_16 33·K_44 15 co-load, C 창 = 처음 128 동거 iteration) → ρ의 검출력은 자연 부하 f와 무관. "STOP = Job-EA 검출력 없음"은 범주 오류.
- 부하 영역이 다르다: N3 k=3 자연 부하는 decode bs ≤ 2, Job-EA 셀은 b ∈ {8, 32}.
- shape가 다르다: shape B는 TTFT 구속이라 DS-3(ITL 쪽)이 판정을 바꾸기 어렵고, DS-3가 닿는 곳은 shape A(보류). shape B만으로 STOP하면 주로 shape A에 쓸모 있는 측정을 취소한다.
f가 말할 수 있는 것은 "N3 shape B 자연 부하에서 동거 구간이 얼마나 흔한가"(기술값)뿐 — 자원 우선순위 입력은 될 수 있다.

## 2. 질문별 요지
- Q1: 규칙의 f = 코드 `coresidency_a_decode`(|PF∩DEC|/|DEC|)인데 공개된 "CO-a"는 `coresidency_a_wall`(분모 = 창) — 필드 고정 필요. 시간선 정의("연속한 이벤트로 덮이는 구간")는 코드(DEC = ∪[t_launch, t_sync])와 어긋나며 STOP 쪽 자유 표면. "self-test v2 16중 11 실패, 상향 편향"은 HE0 클라이언트 재구성 추정량이라 N3 서버측 CO-a에는 해당 없음; 이 관문에서 위험한 편향은 하향(거짓 STOP). 현행 `selftest_synthetic`은 `coresidency_a_wall`만 시험하고 `_decode`는 미시험, 규칙의 "self-test 통과"는 사양 없음.
- Q2: f×Δ 상한 논증은 타당하지 않음 — STOP은 자원 결정으로만 기록(R-1).
- Q3: f_up(Job 최대 × seed 최대)은 방향은 맞으나 원값 병기 필요; "용량 셀" 미정의 → 절대 rate 고정; k=3만 쓰면 STOP 쪽으로 기움(N3VR-16 벽시계 (64,44) 점유 k=3 0.04–0.07, k=5 0.39–0.43, k=10 0.85–0.93 — 대리 지표); k=5·10 `UNSTABLE`은 용량 라벨 크기에 대한 것이라 f 제외 사유로 오적용.
- Q4: Δ 0.15–0.30은 출처 없음. KISTI C2(2.36–2.91×)는 기판 다름·인용정지 하 존재 증거만 — 그것으로 τ=3%/Δ 계산 시 1.6–2.2%로 후보 10–20%보다 4.5–12.7배 엄격. κ 1.3–1.6은 Δ 아님; Job-PROFILE D-민감도는 단독 조건이라 동거 Δ 상한 아님. ⇒ 3%/Δ 도출 폐기.

## 4. 필수 수리
R-1 STOP = "자원 결정: Job-EA 제출 보류(효과 주장 없음)", f×Δ 문단 삭제 또는 "동기 서술, 판정 근거 아님". R-2 τ를 사용자 가치 판단 상수 τ_res로, 안 0 포함. R-3 f := `coresidency_a_decode` 그대로(DEC = ∪[t_launch, t_sync], PF = 짝지은 span 합집합, bench 창 절단), 병기 `coresidency_a_wall`·`decode_active_frac`·g·`prefill_kernel_done_wait` 제외판. R-4 E2 r2 입력 제외(또는 스냅숏 (b)형 기술값만). R-5 self-test 사양 등록(`_decode` 기지값 시간선 ≥3개·HE0와 다른 생성 규칙, 변이: 분모 wall↔decode·교집합→합집합·간격 포함 DEC·span 짝 끊기·창 절단 제거·dropped/R7 무효화 제거, 무변이 대조·KILL 전수, 하향 편향 시험, HE0 v2 인용 정정). R-6 부하점 = 각 Job의 0.15와 0.22, 관문 값은 둘의 max, 0.45·0.69 기술 병기. R-7 블라인드 공시(wall 분모 CO-a 기공개 + 감사자 부분 노출). R-8 모든 f 인용에 "PHASE_EVENTS ON 조건에서". R-9 UNRESOLVED 뒤 수리는 비데이터 사유 + 델타 감사 + 이전 값 병기.

## 5. Caveat
CG-1 "이 관문은 wall 분모 동거율이 이미 공개된 상태에서 등록됐다. 블라인드는 decode 분모 f와 prefill 분모 g에만 성립한다." · CG-2 "τ는 사용자 가치 판단 상수다. 재배분 효과 크기에서 도출되지 않았다." · CG-3 "f는 N3 shape B 자연 부하(decode bs ≤ 2 영역, PHASE_EVENTS ON)의 동거 빈도다. Job-EA 셀(b 8/32)·shape A·다른 config의 동거를 말하지 않는다." · CG-4 "이 관문의 결과는 Job-EA ρ의 검출력, 재배분 효과의 유무·크기, 기여 2(재배분 가능 경계)에 대해 아무것도 말하지 않는다." · CG-5 "두 Job의 f는 서로 다른 GPU에서 측정됐다. 일치는 재현이 아니다(교훈 274)."

## 6. 기록 문안
STOP 허용: "PHASE_EVENTS ON 조건에서, N3 shape B 3·4회차 Job(…)의 등록 부하점 0.15·0.22 req/s에서 정의 (a) 동거율 `coresidency_a_decode`와 prefill 분모 동거율 g의 Job별·seed별 최대가 사용자 결정 문턱 τ_res = __% 미만이었다. 이에 따라 Job-EA 제출을 보류한다(자원 결정). 이 기록은 재배분 효과의 유무·크기, Job-EA의 검출력, 기여 2에 대해 아무것도 말하지 않는다." GO 허용: "… τ_res 이상 → Job-EA를 진행한다(E14-1 재승인 필요). 동거율은 Job-EA 결과의 크기·방향을 예측하지 않는다." 금지: "재배분 효과는 3% 미만", "주장 2는 검출력이 없다", "f×Δ < 3%이므로…", "Job-EA는 돌려도 의미가 없다", "동거가 드물어 SM 재배분은 중요하지 않다", "shape A·다른 config에서도 동거율이 낮다", "3·4회차에서 동거율이 재현됐다", wall 분모 CO-a를 f로 인용, PHASE_EVENTS ON 접두 누락, "블라인드 상태에서 τ를 정했다"(CG-1 없이).

## 7. 실현가능성
R-3·R-6은 기존 필드로 CPU 구현 가능, g는 `measure(pf)` 한 줄. R-5는 HE0 v2 선례처럼 import 후 소스 치환. 요청 단위 노출은 재구성 편향을 다시 들여 처방에서 제외. 안 0은 감사 우회가 아니라 이 질문에 결정 규칙을 둘 estimand가 없다는 결론. 새 성능 판정 0건.
