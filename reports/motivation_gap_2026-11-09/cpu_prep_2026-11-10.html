도착 trace와 간섭 셀 짝 설계

  • 등록 seed 20261111, 20261112, 20261113, 20261114 (예비 20261115, 20261116). 마스터 해시는 trace_registry.json에 봉인되어 있고, rung은 (워크로드, seed, rate, 시간)으로 재현된다. 마스터의 도착 시각은 rate와 무관한 단위 Poisson이고 요청 순서는 풀 순열이므로, 모든 rung이 같은 요청 순서를 쓴다.
  • 간섭 셀: 같은 seed에서 짧은 스트림(사용자 첫 발화 ShareGPT 마스터의 prefix)을 고정하고, LooGLE 스트림을 전체 요청의 5%가 되도록 얹는다. 긴 요청 도착은 개수 고정 Poisson(n_long = round(0.05/0.95 · λ_short · T), t_k = T·S_k/S_(n+1))이라 300초당 도착 건수 잡음이 없다. with_long과 without_long trace의 차이는 긴 요청 레코드뿐이며, 짧은 스트림 해시가 일치함을 검사한다(gen_traces.py seal, 테스트 10개 통과).
  • 예시(잠정 rate 3.0 req/s, seed 20261111): 짧은 891건·긴 47건, 짧은 스트림 해시 91977aec9f048f56…, with d87098807ebbb707…, without d22e520e178d61e4…. 잠정 rate 격자는 사전 사다리 후 봉인한다.

hybrid 항이 D 선택을 바꾸는 셀 예측, 인용 금지

dstar_model 제안 r0(결정 61, 정본 아님) + analytic_terms. 실측 아님. 재생성: reports/motivation_gap_2026-11-09/hybrid_term_cells.py. 항 제거는 decode 상태 트래픽 b0(D) = b0/u(D). 입력 길이 대역은 실제 풀에서 잘랐다. LooGLE 단독은 TTFT 3 s로 전 D 불가라 퇴화 처리한다.

읽는 법: 갈리는 셀은 모두 항을 빼면 D*가 격자 한 칸 작아지는 방향이다(입력 약 256–8k 구간). 워크로드 전체 셀에서 안정적으로 갈리는 것은 openchat 라운드뿐이다: 포함 모델 D*=34, 제거 모델 D*=24, 포함 모델 안에서 λ_cap은 D34 2.30, D24 1.81 req/s. 사용자 첫 발화 ShareGPT와 초록 길이 arXiv 요약은 갈리지 않고, 관측 자연 출력 arXiv 요약은 ρ 1.13에서만 갈리며 λ 차이가 0.01이다. 격자가 성겨 차이는 한 칸 이내로만 읽는다.

전체 108셀(워크로드·입력 대역 × cap {48, 128} × ρ {1.13, 1.16, 1.19}) 중 hybrid 항을 빼면 D*가 달라지는 셀: 보정 방식 56, predict.py 방식 40 (이 가운데 보정 방식에서는 안 갈리는 셀 0). 람다 상한이 전 D에서 0인 퇴화 셀 6.

vLLM 0.31.0에서 a31 조성 변형 로드 가능성 (코드 확인, 미실행)

  • a31은 make_variant.py가 Nano config의 hybrid_override_pattern만 바꾼다(27개 Mamba 층 전부 → *, 31 attention · 0 Mamba, MLP 25층). 이미지 ghcr.io/asuan99/sglang-vllm-runtime:0.31.0-09df5f34의 /opt/vllm-venv 코드를 읽어 확인했다. 실제 로드는 하지 않았다(GPU 없음, 이미지 안에서 코드 실행도 안 함).
  • 로드 경로에 Mamba 층 존재를 요구하는 검사가 없다: 레지스트리 NemotronHForCausalLM→nemotron_h.py; 층 생성은 패턴 문자별(nemotron_h.py:596-605, * 허용); config 검증은 길이·문자 집합만(transformers_utils/configs/nemotron_h.py). transformers의 NemotronHConfig도 패턴을 층 목록으로 변환해 받는다(configuration_nemotron_h.py:157-165). KV spec은 attention 모듈에서 수집하므로 31개 attention spec만 생긴다(gpu_model_runner.py:7435-7455, MambaSpec 없음).
  • 주의 1 — block size: NemotronHForCausalLM은 클래스 속성으로 IsHybrid이며 config의 mamba_* 값은 남아 있어 _align_hybrid_block_size(platforms/interface.py:835-1016)가 그대로 돈다. 실제 Nano 부팅의 기록은 attention block size 1,312 토큰(Phase B vLLM server.log, interface.py:989)이다. 이 코드 경로대로면 a31도 같은 1,312 토큰이 될 것으로 유도된다(미실행). a31은 Mamba 상태가 없는데 attention 할당 단위만 1,312 토큰 × 31층이 되어 짧은 요청이 한 블록(약 167 MB, k = 126,976 B/토큰은 make_variant 값)을 차지한다.
  • 주의 2 — 이 값은 SGLang과 다른 축: compo_probe의 SGLang 부팅에서 a31은 정상 부팅·배너 일치(results/cap_char/compo_probe/RESULT_compo_probe_2026-10-21.md:31-36). vLLM·a31 비교를 쓰려면 vLLM 쪽 block 단위 차이를 공시하거나 끌 방법(변형 config에서 mamba 필드 0 처리, 미검증)을 정해야 한다.
  • 판단: 코드상 로드 가능, 단 실측 부팅(a31 dummy) 전까지는 '로드 확인'이 아니다.
